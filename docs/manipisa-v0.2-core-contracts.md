# ManipISA v0.2 六条核心指令契约草案

本版采用用户选定的六条核心指令：SHAPE_HAND、MAKE_CONTACT、BREAK_CONTACT、MOVE、CONTROL_GRASP、APPLY_WRENCH。精简指令集思想继续约束设计：控制目标保持明确，实体差异由带类型的操作数表达，执行时长和进入条件由公共契约表达，复杂任务由程序组合。

本版补齐合并时必须保留的进入条件、动作范围、证据绑定和阶段约束。原 v0.1 的九条基础候选在这些显式条件下可以建立契约层面的映射。原扩展候选 TRANSFER_SUPPORT 的整体替代关系仍待程序级验证，不计入核心，也不宣称已由六条完整覆盖。

本文件是完整语义的设计规范草案。Runtime 与 Isaac Lab 已接通六个操作码：空闲空间构型/位姿，以及有界接触、分离、准静态抓持与位置导纳施力。当前实现尚不覆盖本规范的全部参数组合，尤其是动态承载、实体运动与共享对象并发协调。接口与限制见 [Runtime 说明](../README.md) 和 [接触执行说明](manipisa-interaction-runtime.md)，验证证据见 [运行记录](manipisa-runtime-validation.md)。配套文档：[语义保留验证](manipisa-v0.2-semantic-preservation.md)。历史基线：[v0.1 指令契约](manipisa-v0.1-instruction-contracts.md)。

## 六条核心指令

| 指令 | 物理目标 | 本版支持的执行模式 |
| --- | --- | --- |
| SHAPE_HAND | 指定手角色的内部构型 | REACH |
| MAKE_CONTACT | 指定接触关系成立 | REACH |
| BREAK_CONTACT | 指定接触关系在物理上解除 | REACH |
| MOVE | 指定目标坐标系的位姿或轨迹 | REACH、SUSTAIN |
| CONTROL_GRASP | 指定已有接触集合的抓持条件 | REACH、SUSTAIN |
| APPLY_WRENCH | 指定交互接口的力与力矩 | SUSTAIN，可用显式结束条件限定执行时长 |

公共模式字段不意味着每条指令都自动支持所有组合。不支持的模式返回 UNSUPPORTED_CAPABILITY，不能静默替换为另一种行为。本版没有为不涉及此次合并的指令额外增加持续模式。适配层的接口约定与执行准备检查必须覆盖操作码、目标绑定类型、执行模式、可控方向、证据条件和支持的并发组合；不能由一个操作码的支持声明推断所有组合都受支持。支持范围可以由固定 Adapter 实现表达，不要求独立能力描述对象或能力发现服务。

SHAPE_HAND、MAKE_CONTACT、BREAK_CONTACT、APPLY_WRENCH 沿用原物理职责。旧名称的映射只用于契约迁移，不成为额外核心操作码。观察、判断、等待、更新和编排仍属于公共执行协议；六条是物理操作码数量。

## 抽象操作数

| 类型 | 含义与限制 |
| --- | --- |
| Actor | 可以执行动作的资源或资源集合。参与者数量通过集合表达，名称不携带左右或型号语义。 |
| Entity | 被操作的物体、部件或环境实体。实体类别不决定操作码。 |
| TargetRef | 被控制的坐标系，包含拥有者类型、实体或参与者标识与坐标系标识；证据必须对应该目标。 |
| GraspSpec | 期望的抓持条件，包含已有接触集合、作用对象、负载能力要求和允许相对运动；不要求抓持预先成立。 |
| Frame | 用于表达位姿、速度或力的坐标系。必须给出绑定实体、来源与有效性。 |
| Region | 实体上的允许交互区域；可以是点、曲线、表面或体积。 |
| ContactSet | 具名接触关系集合，包括两侧区域、接触状态和允许的接触行为。句柄存在不代表接触当前成立。 |
| GraspRelation | 指定接触集合、作用对象、允许运动、负载要求及成立证据组成的抓持关系。 |
| SupportSet | 参与承载的具名接触集合，可包含受控参与者和被动环境支撑。被动支撑不能被当作可直接命令的执行器。 |
| ControlHandle | 正在执行或仍保留控制作用的句柄，用于查询、更新、停止和控制权移交。 |

SHAPE_HAND 中的 Hand 是能力角色。构型参数由适配层的构型接口与绑定配置给出，不能在 ISA 中固定手指数、关节数、传动方式或某个型号的姿态模板。

位姿采用三维刚体变换语义，空间量使用右手坐标系。长度、角度、时间、力、力矩分别使用 m、rad、s、N、N·m。序列化表示将在后续接口规范中确定，不能由调用者和适配器各自猜测。对柔性实体，只能承诺所声明可观测特征坐标系的目标；材料形变控制不在本草案中自动获得支持。

所有参考系必须注明 SNAPSHOT 或 LIVE。SNAPSHOT 固定在指定时间的观测；LIVE 随绑定对象更新。位置误差和速度条件相对于所选参考系计算。参考系观测过期时不能继续当作有效数据。

接触行为必须显式声明，例如粘着、允许滑动或允许滚动，以及允许的区域和限值。接触点可以在许可区域内移动；禁止新增或解除接触关系不等于冻结接触点的数值坐标。

## 公共契约

每次调用经过解析后，必须得到下面这些可审查信息。工程配置可以提供默认值，但解析后的完整值必须可查询。

| 字段 | 内容 |
| --- | --- |
| operation | 操作码与语义版本 |
| actors | 执行参与者，以及解析后的控制资源 |
| operands | 对象、部件、坐标系、接触和关系引用 |
| goal | 目标值、受控方向、容差与必要的连续满足时间 |
| preconditions | 执行前必须成立的条件及所需证据 |
| allowed_changes | 许可的主动动作、接触拓扑变化和有界调整范围 |
| invariants | 执行期间必须保持的条件 |
| termination | 成功条件、显式结束条件、时限及取消响应要求 |
| continuation | 完成、失败和取消后的控制去向 |
| evidence_policy | 观测来源、时效、监测频率、最大检测延迟及不确定性处理 |

allowed_changes 界定许可的主动行为。物理耦合可能影响其他状态；需要保持的量必须列入 invariants 并被监测，不能从“未列入允许变化”推断它恒定。持续约束可以明确标注适用阶段；未标注时，从开始执行到控制移交完成均适用。

受控方向用明确的坐标基与方向选择描述；需要一般子空间时必须声明基底。MOVE 在 REACH 和 SUSTAIN 模式下均允许只约束部分自由度。APPLY_WRENCH 的力与力矩参考点必须显式给出，跨参考点转换必须计入力矩变化。

抓持负载要求必须明确作用对象、参考系、力矩参考点和有效时间范围，并包含所声明任务需要的重力、外部作用和动态负载。静态或准静态证据不能直接作为动态能力的证明。抓持的可承受负载集合与参与者当前必须承担的实际载荷分开表示；前者属于能力要求，后者属于分配约束。不能仅凭“仍然具有承载能力”推断“正在承担该载荷”。参与成立证明的被动支撑必须列为证据依赖；移除或改变依赖后需要重新验证，不能把联合支撑证明沿用为独立抓持证明。

### 观测与证据

条件判断采用 SATISFIED、VIOLATED、UNKNOWN 三值语义。未知、失效或过期观测不能计为成功。已有抓持证据只在其负载范围、接触条件、模型假设和时效范围内有效。必要谓词出现 UNKNOWN 时，本轮连续满足时间清零；检测和失效响应仍遵循声明的 evidence_policy。

成功必须来自与目标对应的观测或声明过的估计证据。末端位姿不能无条件替代物体位姿；电机命令不能无条件替代接触力；接触存在不能替代承载成立。允许估计时，结果必须携带方法、误差界或置信信息及假设。

能力不足、关键目标不可观测、前置条件不满足或静态检查发现冲突时，运行前拒绝请求。运行中失去必要证据时，按约定的检测延迟和控制退路处理，并报告 UNKNOWN 及相应失败原因，不能假称物理条件已经违反或仍然成立。

### 生命周期与控制去向

有限动作在目标及其连续满足时间得到验证、且全过程适用约束均满足后返回 SUCCEEDED。持续模式先进入 RUNNING，在激活条件成立后进入 ACTIVE；进入 ACTIVE 不代表模式已经完成。

持续模式在显式规定的时长或正常结束条件满足、且全过程契约满足时，才能返回 SUCCEEDED。调用者提前停止使用 CANCELED；违反契约或超时使用 FAILED。尚未执行就不能接受的请求使用 REJECTED。

有限动作的执行时限和模式的激活时限从实际开始执行时计时，排队等待另设上限。持续模式的维持时长从进入 ACTIVE 时计时；总执行预算单独限制激活与维持的合计时间。达到终点后恢复正常不能抹去之前的硬约束违反。FAILED 对同一次调用保持为终态；更新目标或重新满足目标不能使其恢复为成功。需要再次尝试时使用新调用，保留原失败记录。

物理结果和控制权去向分别报告。每个请求必须指定以下一种完成后处理：

- 将控制权连续移交给已准备好的后继操作。
- 在明确的期限内继续保持已声明的控制目标，并返回仍然占用资源的 ControlHandle。
- 在经验证允许的状态下结束该控制作用。

目标验证和 continuation 的接续建立共同确定本次调用的完成边界。后继尚未就绪时不能静默撤销旧控制；保留控制的分支必须先建立明确的剩余 ControlHandle。旧调用完成后的持续作用由该句柄的契约报告健康状态，旧调用的成功不承诺未来无限保持。

延续已有控制目标不会自动扩大抓持或承载保证。后继接管和旧目标撤销必须在同一运行时的控制边界上协调，并满足声明的切换时限；控制权切换不意味着物理世界瞬间发生原子变化。

失败与取消也必须返回仍在运行的控制句柄、已经发生的物理变化和最新证据。运行时执行预先声明的有界退路；若无法满足退路条件，明确报告实际结果。取消不会自动释放全部接触，失败也不承诺物理回滚。

### 并发与更新

并发许可同时检查资源重叠与物理目标兼容性。不同名称的 Actor 可能共享同一驱动资源；不同 Actor 也可能通过同一个物体形成耦合。

冲突检查按解析后的物理资源、目标实体、接触关系、受控方向及硬约束进行，不能按操作码名称或调用句柄是否相同来判定。

兼容目标交给一个协调执行层处理。无法证明并发可行时拒绝或要求显式排序，不允许后一条命令静默覆盖前一条。并发能力也必须由实现声明。

运行中的目标、负载或约束更新必须重新校验。改变抓持关系的接触成员、放宽旧承载义务或移交控制权，都需要显式更新；更新被接受前，旧契约仍然有效。放宽声明不会立即改变实际接触力。改变成员的更新必须引用已经重新验证的新 GraspRelation，不能只修改列表并延续旧成立证明。更新不改变操作码；扩大动作范围或新增能力需求必须重新接纳请求。

当物体运动引起新的动态负载时，CONTROL_GRASP 使用的负载范围必须覆盖它，或者先完成经过验证的更新。

## 合并后必须显式表达的信息

### 控制目标与执行参与者

MOVE 的 controlled_target 是 TargetRef；actors 是实现运动的执行资源；reference_frame 是表达目标的参考系。三者不得混用。

TargetRef 明确绑定 ACTOR_FRAME 或 ENTITY_FRAME，并解析其拥有者与观测身份。名称或别名相同不构成相同观测的证明；指向同一物理目标的别名也必须被解析为同一目标。

控制实体坐标系时，所需 interaction_refs 必须说明参与者通过哪些已有交互影响实体。控制参与者自身坐标系时，不强制新增物体抓持条件，但仍保留原请求声明的接触和关系约束。

evidence_target 必须与 controlled_target 相同，或由显式声明且满足误差要求的观测变换得到。末端与物体之间的关系不可观测、变化或发生滑移时，不能继续无条件用末端测量代替物体测量。

### 执行模式与进入条件

execution.mode 只描述达到目标后的执行方式：

- REACH：达到目标并完成连续满足时间验证后结束；实际退出控制仍遵循 continuation。
- SUSTAIN：达到激活条件后进入 ACTIVE，持续满足目标，直到指定正常结束、取消或失败。

entry_guard 独立规定开始执行前必须成立的条件。它在控制实际生效或接管前重新验证，不能只在排队或准备阶段检查一次。进入时证据为 UNKNOWN 的必需条件不能自动改为“执行后再尝试满足”。

acquisition_domain 独立规定目标尚未满足时允许的状态范围、调整幅度和动作。必须保留原调用的范围；SUSTAIN 不会自动授权远距离接近、重抓或大范围移动。

对原 MAINTAIN_GRASP 的映射，entry_guard 必须要求抓持当前有效，并把该抓持条件列为从接管开始就持续生效的约束。只指定 SUSTAIN 不能保留原语义。

对原 HOLD_OBJECT 的映射，entry_guard 必须要求对象已经在保持容差内或指定捕获范围内，acquisition_domain 仅允许该范围内的恢复。对象远离捕获范围时拒绝请求，不能自动转为搬运。

### 阶段约束与证据时间

目标是否达到与持续约束是否满足分别判断。约束可绑定整个执行过程、目标获取阶段或 ACTIVE 阶段；未标注阶段时采用公共规则的整个控制区间。

原 MAINTAIN_GRASP 的有效性义务从开始接管就生效。原 HOLD_OBJECT 允许先在有界范围内捕获目标，严格保持容差从 ACTIVE 开始生效，捕获期间仍受原运动与载荷限制约束。

每个证据绑定目标、参考系、时间、方法、有效范围和依赖。连续满足时间只能使用符合 evidence_policy 的判断累积；UNKNOWN 或已确认的违反打断该时间，不能把缺失时段补成成功。

同一调用发生硬约束违反后保留失败结果。允许的有界退路可以改善物理状态，但不会消除既有失败，也不自动重新进入成功的维持阶段。

### 控制权与并发身份

REACH 调用结束后，如果仍需控制来维持物理状态，必须返回持续占用资源的 ControlHandle，或完成向后继的连续移交。该剩余控制作用与 SUSTAIN 的完整目标保证分开记录，不能将“保留驱动输出”当成“已验证的持续抓持”。

合并为相同操作码不会使并发目标自动相容。两条 MOVE 作用于同一物体的同一方向时，照常检查目标兼容性；不同目标通过接触或机构形成耦合时，也必须共同检查。

暂停、取消、超时或证据失效时，按作用范围处理受影响的控制分支。不能因一个 MOVE 被取消而静默取消共享物体上的抓持，也不能保证其他分支必然仍然可行；剩余分支的实际状态和失败需要重新报告。

## 六条指令契约卡

### SHAPE_HAND

- **操作数**：手角色、适配层构型接口支持的目标构型、变化速率、容差和允许调整范围。
- **前置条件**：目标构型维度受支持，状态可观测，资源可用；保留的位姿、接触和抓持约束具有可行解。
- **允许变化与持续约束**：在限值内调整内部构型，保持原请求指定的末端位姿、接触、抓持和载荷条件。自动建立或解除接触不属于该目标。
- **成功证据**：对应手的实际构型误差和相对变化速度满足阈值，并持续规定时间；整个适用区间内的约束满足。
- **并发限制**：与 MOVE 或其他构型目标共同检查实际控制资源和保护关系；不能通过覆盖其他命令完成构型。
- **失败行为**：保留目标不可行、资源或目标冲突、约束违反、证据失效和超时等原因；取消与控制移交遵循公共规则。

### MAKE_CONTACT

- **操作数**：参与者、源与目标区域、待建立 ContactSet、接近范围、接触判据和连续满足时间。
- **前置条件**：目标区域及接近范围明确，局部接近受支持，必要状态可观测，受保护的已有接触有效。
- **允许变化与持续约束**：只在允许范围内通过末端或内部构型调整建立目标接触，保护其他指定接触，保持对象运动与载荷界限。
- **成功证据**：全部指定接触满足各自判据和连续满足时间，返回具名接触证据。接触成立不自动产生 GraspRelation。
- **并发限制**：新接触的形成必须与其他 CONTROL_GRASP 或 MOVE 的保护要求相容。不能静默改变正在维护的抓持成员列表。
- **失败行为**：错误区域接触、保护接触丢失、对象运动或载荷超限、证据失效与超时均不能成功；需要较大范围搜索时由外部程序重新安排。

### BREAK_CONTACT

- **操作数**：待解除 ContactSet、参与者、允许分离动作范围、分离判据及连续满足时间。
- **前置条件**：关系可识别，分离受支持；剩余抓持和承载契约已经适配移除后的关系，控制权可接管。
- **允许变化与持续约束**：在范围内解除指定接触，保护其他接触、物体运动界限和仍有效的承载义务；不隐式承担承载迁移。
- **成功证据**：目标接触在物理上消失，达到几何间隙或等价的已声明判据并持续规定时间。零接触力或删除句柄均不足以证明分离。
- **并发限制**：与要求保留同一接触的 CONTROL_GRASP 冲突；必须先完成有效的关系更新或控制移交。
- **失败行为**：残留接触、非目标关系破坏、承载或资源冲突、证据失效与超时分别报告，禁止通过解除全部接触代替局部解除。

### MOVE

- **操作数**：controlled_target、actors、interaction_refs、reference_frame 及 SNAPSHOT 或 LIVE 绑定、目标位姿或轨迹、受控方向、容差、entry_guard、acquisition_domain 和 execution.mode。
- **前置条件**：被控制目标可观测或有满足声明误差的估计；实施运动的能力与交互关系有效；原请求的进入、范围和资源条件满足。ENTITY_FRAME 不自动要求抓持，但必须有支持所请求运动的交互方式。
- **允许变化与持续约束**：只执行声明轨迹、范围和接触行为允许的运动与配置调整；保持指定接触、抓持、载荷和其他目标条件。固定目标加 SUSTAIN 仅允许请求授权的捕获与扰动补偿。
- **成功证据**：始终检查 controlled_target 自身的实际位姿或轨迹误差，以及原请求规定的相对速度、连续满足时间和阶段约束。REACH 按有限动作结束；SUSTAIN 激活后持续验证，正常结束时才报告成功。
- **并发限制**：统一检查目标实体、方向、接触耦合及控制资源。固定目标的 SUSTAIN 与不相容的运动目标冲突；与 APPLY_WRENCH 的组合必须由实现支持的协调控制处理。
- **失败行为**：目标不可达、轨迹或保护关系违反、目标观测未知、资源冲突、超时和取消保留原区别。已发生的保持容差违反不能被后续恢复抹去；不能因末端已到位而误报对象目标成功。

### CONTROL_GRASP

- **操作数**：GraspSpec、参与者、已有 ContactSet、允许构型与力调整、entry_guard、acquisition_domain、execution.mode，以及要求进入时有效时必须提供的最新关系证据。
- **前置条件**：指定接触已成立，负载能力要求、参考系和证据范围明确，调整能力受支持。GraspSpec 描述目标，允许当前抓持尚未成立；是否必须已有有效抓持由 entry_guard 明确规定。
- **允许变化与持续约束**：在相同接触成员和允许行为内调整预紧、构型和接触力，满足目标及阶段约束。允许相对运动、动态负载、外部支撑依赖和实际承载分配条件分别记录，不自动固定世界位姿。
- **成功证据**：REACH 验证指定接触集合满足所需抓持条件、稳定性指标和连续满足时间，返回 GraspRelation 及有效范围；SUSTAIN 激活后继续验证，达到正常结束条件时才成功。当前接触存在不能替代负载能力证据。
- **并发限制**：与 MOVE、APPLY_WRENCH 共同检查目标、真实资源及实际载荷约束。保留“具备某承载能力”与“当前必须承担该载荷”的区别，避免错误判断卸载冲突。成员变更必须引用已重新验证的新关系。
- **失败行为**：REACH 期间条件尚未达到是目标获取状态，但预算耗尽、硬约束违反或证据失效仍失败。要求有效抓持进入的请求在入口失效时拒绝；执行中受保护抓持丢失报告 GRASP_INVALID 或 CONTACT_LOST。禁止静默退回重抓、新增接触或把失败改为继续成功。

### APPLY_WRENCH

- **操作数**：施力参与者、受力对象、具名交互接口、表达坐标系、力矩参考点、六维目标、受控方向、变化率和终止条件。
- **前置条件**：所需接触存在，接口能实现目标，必要力或力矩证据有效，参与者和其他控制目标相容。
- **允许变化与持续约束**：在限定构型和运动范围内施力，保持指定接触、抓持和对象运动条件，遵守各接触及执行器限值。
- **成功证据**：检查指定接口在指定参考系和参考点的作用力与力矩；方向规定为参与者通过该接口作用在对象上。满足连续时间后激活，再持续到约定结束。聚合接口合力不能替代单个接触的载荷证据。
- **并发限制**：运动与力目标在声明的方向和物理约束下共同求解，不能以独立写入底层命令代替协调。多个接口满足各自目标不自动证明整体承载转移成功。
- **失败行为**：失去必要接触、载荷达不到、证据不足、约束或资源冲突、超时等保留。该指令不能自动建立接触，也不能隐式承担未声明的全局承载义务。

## 返回结果与失败原因

结果至少包含 operation_id、生命周期状态、各目标和约束的三值判断、达成状态及时间戳、证据与假设、有效的接触和关系、仍在运行的控制句柄、实际发生的物理变化，以及具体失败原因。

建议使用下列语义原因族，具体编码格式后续冻结：

| 原因族 | 含义 |
| --- | --- |
| INVALID_REQUEST | 引用、单位、参考系、目标或契约不完整 |
| UNSUPPORTED_CAPABILITY | 实现不支持该操作所需能力 |
| PRECONDITION_UNSATISFIED | 前置条件被证据判定不成立 |
| EVIDENCE_UNAVAILABLE | 必要证据缺失、过期或精度不足 |
| INFEASIBLE_GOAL | 所声明模型及约束下目标不可行 |
| RESOURCE_OR_GOAL_CONFLICT | 控制资源或物理目标无法协调 |
| CONTACT_LOST | 要求保留的接触失效 |
| GRASP_INVALID | 抓持关系不再满足要求 |
| SUPPORT_INSUFFICIENT | 承载或接管条件不足 |
| CONSTRAINT_VIOLATION | 其他持续约束被违反 |
| TIMEOUT | 时限内未完成或未激活 |

失败原因可以并列出现，并保留首个相关时间。指令局部成功不自动等于任务整体成功；程序和基准仍需检查全过程约束及最终任务条件。

## 原指令的规范映射

所有映射均原样携带原请求的 actors、交互关系、目标值、证据要求、允许变化、持续约束、预算、退出方式与失败分支。表中只列合并所需的额外区分，不允许遗漏其他字段。

| 原指令 | 新操作码 | 必须保留的区分 |
| --- | --- | --- |
| SHAPE_HAND | SHAPE_HAND | 原构型目标与 REACH 契约 |
| MAKE_CONTACT | MAKE_CONTACT | 原接触目标与 REACH 契约 |
| BREAK_CONTACT | BREAK_CONTACT | 原解除目标与 REACH 契约 |
| ESTABLISH_GRASP | CONTROL_GRASP | REACH；已有接触是前置，抓持成立是目标；允许有界调整 |
| MAINTAIN_GRASP | CONTROL_GRASP | SUSTAIN；进入时抓持必须有效；从接管开始持续保护有效性 |
| MOVE_EE | MOVE | ACTOR_FRAME；REACH；目标证据来自指定末端 |
| MOVE_OBJECT | MOVE | ENTITY_FRAME；REACH；交互关系及对象证据必需 |
| HOLD_OBJECT | MOVE | ENTITY_FRAME；固定相对目标；SUSTAIN；保留有界捕获入口和 ACTIVE 保持义务 |
| APPLY_WRENCH | APPLY_WRENCH | 原 SUSTAIN、接口、坐标系与力矩参考点契约 |

原 MAINTAIN_GRASP 不得仅翻译成“CONTROL_GRASP 加 SUSTAIN”。原 HOLD_OBJECT 不得仅翻译成“MOVE 加 SUSTAIN”。缺少进入条件和动作范围的映射属于不完整翻译。

如果旧请求的目标身份、进入条件、能力要求或实际载荷义务无法确定，翻译时返回 INVALID_REQUEST 或要求补全设计配置，不猜测其含义。本版的保留结论针对已解析、条件明确的旧契约实例。

## 承载转移的验证边界

TRANSFER_SUPPORT 不属于六条核心。它原来同时承诺接触集合不变、整体承载连续、分配进入目标范围、接管方在需要时可独立承载，以及新分配在退出后的连续维持。

由多个 APPLY_WRENCH、必要的 CONTROL_GRASP 或 MOVE 和公共编排组成转移程序，只是一个待验证的实现方向。单个分支完成不能推出全局程序完成，简单顺序执行“先卸载、再加载”也不满足连续承载要求。

至少需要以下程序级条件才能进一步论证等价：

- 一个协调执行层同时处理来源和目标的载荷目标，并监测整个对象的承载与运动约束。
- 在同一有效观测区间中验证来源卸载、目标加载和整体平衡；不能拼接不同时间的成功证据。
- 计划解除来源时，对剩余支撑独立满足负载要求给出有效证据，并持续维持该状态。
- 更新实际载荷义务、控制权移交与异常退路覆盖全部相关分支，不能产生无承载的控制间隙。
- 被动环境支撑的载荷通过可行的受控交互改变，并具有足够观测，不能把被动支撑直接当作执行器命令。

当前六条核心及单条契约没有单独证明这些程序级条件能够实现。缺少相应程序能力的实现必须明确拒绝该转移任务；不能以已支持 APPLY_WRENCH 或 CONTROL_GRASP 为由宣布支持完整转移。

## 本版验证范围

验证使用 v0.1 的九条基础候选作为逐项映射基线；TRANSFER_SUPPORT 的四项检查独立列为未闭合。详细对应、反例和证据边界见[语义保留验证](manipisa-v0.2-semantic-preservation.md)。

本轮只验证契约表达和逻辑规则，没有执行运动、力控制、接触或承载实验，也没有运行形式化证明器。适配器能否提供必要观测、协调控制和时间保证仍需验证。
