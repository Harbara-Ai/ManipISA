# ManipISA v0.1 指令契约草案

本草案定义与具体机器人、控制器和仿真器解耦的操作语义，供指令集评审和后续实验使用。当前建议为 9 条基础物理指令候选和 1 条协同扩展候选。文中的“必须”表示本草案提出的契约要求，不表示现有系统已经实现。

精简指令集思想是持续设计原则：少量稳定的操作语义、明确的操作数和状态变化、统一的执行规则，以及可组合的程序。只有在现有指令组合无法保持必要的物理约束或表达重要效果时，才考虑新增操作码。当前集合尚未证明最小或完备。

日期：2026 年 10 月 3 日。范围：语义设计与纸面审查，不包含代码、控制器实现或仿真实验。

配套文档：[设计复核记录](manipisa-v0.1-design-review.md)。

## 指令集合

| 指令 | 类别 | 执行形态 | 核心承诺 |
| --- | --- | --- | --- |
| SHAPE_HAND | 基础候选 | 有限动作 | 指定手的内部构型达到目标 |
| MAKE_CONTACT | 基础候选 | 有限动作 | 指定接触成立 |
| ESTABLISH_GRASP | 基础候选 | 有限动作 | 已有接触集合达到指定抓持条件 |
| MAINTAIN_GRASP | 基础候选 | 持续模式 | 指定抓持关系持续有效 |
| BREAK_CONTACT | 基础候选 | 有限动作 | 指定接触在物理上解除 |
| MOVE_EE | 基础候选 | 有限动作 | 指定末端达到目标位姿或完成轨迹 |
| MOVE_OBJECT | 基础候选 | 有限动作 | 指定物体或部件达到目标位姿或完成轨迹 |
| HOLD_OBJECT | 基础候选 | 持续模式 | 物体相对参考系的指定位姿分量保持在容差内 |
| APPLY_WRENCH | 基础候选 | 持续模式 | 指定交互接口的力和力矩满足目标 |
| TRANSFER_SUPPORT | 协同扩展候选 | 有限动作 | 已有支撑之间的承载分配达到目标 |

持续模式允许显式指定执行时长或结束条件；达到目标首先产生 ACTIVE 状态。观察、判断、启动、更新、停止、等待和程序编排属于公共执行协议，本文件不将它们计入这 10 条物理指令，也未冻结完整协议的命令数量。

## 抽象操作数

| 类型 | 含义与限制 |
| --- | --- |
| Actor | 可以执行动作的资源或资源集合。参与者数量通过集合表达，名称不携带左右或型号语义。 |
| Entity | 被操作的物体、部件或环境实体。实体类别不决定操作码。 |
| Frame | 用于表达位姿、速度或力的坐标系。必须给出绑定实体、来源与有效性。 |
| Region | 实体上的允许交互区域；可以是点、曲线、表面或体积。 |
| ContactSet | 具名接触关系集合，包括两侧区域、接触状态和允许的接触行为。句柄存在不代表接触当前成立。 |
| GraspRelation | 指定接触集合、作用对象、允许运动、负载要求及成立证据组成的抓持关系。 |
| SupportSet | 参与承载的具名接触集合，可包含受控参与者和被动环境支撑。被动支撑不能被当作可直接命令的执行器。 |
| ControlHandle | 正在执行或仍保留控制作用的句柄，用于查询、更新、停止和控制权移交。 |

SHAPE_HAND 中的 Hand 是能力角色。构型参数由能力描述给出，不能在 ISA 中固定手指数、关节数、传动方式或某个型号的姿态模板。

位姿采用三维刚体变换语义，空间量使用右手坐标系。长度、角度、时间、力、力矩分别使用 m、rad、s、N、N·m。序列化表示将在后续接口规范中确定，不能由调用者和适配器各自猜测。对柔性实体，只能承诺所声明可观测特征坐标系的目标；材料形变控制不在本草案中自动获得支持。

所有参考系必须注明 SNAPSHOT 或 LIVE。SNAPSHOT 固定在指定时间的观测；LIVE 随绑定对象更新。位置误差和速度条件相对于所选参考系计算。参考系观测过期时不能继续当作有效数据。

接触行为必须显式声明，例如粘着、允许滑动或允许滚动，以及允许的区域和限值。接触点可以在许可区域内移动；禁止新增或解除接触关系不等于冻结接触点的数值坐标。

## 公共契约

每次调用经过解析后，必须得到下面这些可审查信息。工程配置可以提供默认值，但解析后的完整值必须可查询。

| 字段 | 内容 |
| --- | --- |
| operation | 操作码与语义版本 |
| actors | 执行参与者，以及解析后的控制资源 |
| operands | 对象、部件、坐标系、接触和关系引用 |
| goal | 目标值、受控方向、容差与必要的连续满足时间 |
| preconditions | 执行前必须成立的条件及所需证据 |
| allowed_changes | 许可的主动动作、接触拓扑变化和有界调整范围 |
| invariants | 执行期间必须保持的条件 |
| termination | 成功条件、显式结束条件、时限及取消响应要求 |
| continuation | 完成、失败和取消后的控制去向 |
| evidence_policy | 观测来源、时效、监测频率、最大检测延迟及不确定性处理 |

allowed_changes 界定许可的主动行为。物理耦合可能影响其他状态；需要保持的量必须列入 invariants 并被监测，不能从“未列入允许变化”推断它恒定。持续约束可以明确标注适用阶段；未标注时，从开始执行到控制移交完成均适用。

受控方向用明确的坐标基与方向选择描述；需要一般子空间时必须声明基底。MOVE 和 HOLD 允许只约束部分自由度。APPLY_WRENCH 的力与力矩参考点必须显式给出，跨参考点转换必须计入力矩变化。

抓持负载要求必须明确作用对象、参考系、力矩参考点和有效时间范围，并包含所声明任务需要的重力、外部作用和动态负载。静态或准静态证据不能直接作为动态能力的证明。参与成立证明的被动支撑必须列为证据依赖；移除或改变依赖后需要重新验证，不能把联合支撑证明沿用为独立抓持证明。

### 观测与证据

条件判断采用 SATISFIED、VIOLATED、UNKNOWN 三值语义。未知、失效或过期观测不能计为成功。已有抓持证据只在其负载范围、接触条件、模型假设和时效范围内有效。

成功必须来自与目标对应的观测或声明过的估计证据。末端位姿不能无条件替代物体位姿；电机命令不能无条件替代接触力；接触存在不能替代承载成立。允许估计时，结果必须携带方法、误差界或置信信息及假设。

能力不足、关键目标不可观测、前置条件不满足或静态检查发现冲突时，运行前拒绝请求。运行中失去必要证据时，按约定的检测延迟和控制退路处理，并报告 UNKNOWN 及相应失败原因，不能假称物理条件已经违反或仍然成立。

### 生命周期与控制去向

有限动作在目标及其连续满足时间得到验证、且全过程适用约束均满足后返回 SUCCEEDED。持续模式先进入 RUNNING，在激活条件成立后进入 ACTIVE；进入 ACTIVE 不代表模式已经完成。

持续模式在显式规定的时长或正常结束条件满足、且全过程契约满足时，才能返回 SUCCEEDED。调用者提前停止使用 CANCELED；违反契约或超时使用 FAILED。尚未执行就不能接受的请求使用 REJECTED。

有限动作的执行时限和模式的激活时限从实际开始执行时计时，排队等待另设上限。持续模式的维持时长从进入 ACTIVE 时计时；总执行预算单独限制激活与维持的合计时间。达到终点后恢复正常不能抹去之前的硬约束违反。

物理结果和控制权去向分别报告。每个请求必须指定以下一种完成后处理：

- 将控制权连续移交给已准备好的后继操作。
- 在明确的期限内继续保持已声明的控制目标，并返回仍然占用资源的 ControlHandle。
- 在经验证允许的状态下结束该控制作用。

延续已有控制目标不会自动扩大抓持或承载保证。后继接管和旧目标撤销必须在同一运行时的控制边界上协调，并满足声明的切换时限；控制权切换不意味着物理世界瞬间发生原子变化。

失败与取消也必须返回仍在运行的控制句柄、已经发生的物理变化和最新证据。运行时执行预先声明的有界退路；若无法满足退路条件，明确报告实际结果。取消不会自动释放全部接触，失败也不承诺物理回滚。

### 并发与更新

并发许可同时检查资源重叠与物理目标兼容性。不同名称的 Actor 可能共享同一驱动资源；不同 Actor 也可能通过同一个物体形成耦合。

兼容目标交给一个协调执行层处理。无法证明并发可行时拒绝或要求显式排序，不允许后一条命令静默覆盖前一条。并发能力也必须由实现声明。

运行中的目标、负载或约束更新必须重新校验。改变抓持关系的接触成员、放宽旧承载义务或移交控制权，都需要显式更新；更新被接受前，旧契约仍然有效。放宽声明不会立即改变实际接触力。改变成员的更新必须引用已经重新验证的新 GraspRelation，不能只修改列表并延续旧成立证明。更新不改变操作码；扩大动作范围或新增能力需求必须重新接纳请求。

当物体运动引起新的动态负载时，MAINTAIN_GRASP 使用的负载范围必须覆盖它，或者先完成经过验证的更新。

## 指令契约卡

### SHAPE_HAND

- **操作数**：手角色集合、能力描述中的目标构型、构型容差、变化速率和允许调整范围。
- **前置条件**：所请求的构型维度受支持，目标可解释，必要状态可观测，执行资源可用。
- **允许变化**：手的内部几何构型及其实现所需的驱动状态。构型目标不包含自动建立抓持、解除接触或安排末端接近。
- **持续约束**：保持显式列出的末端位姿、已有接触、抓持关系和力学限值。构型调整与这些约束不相容时不能以破坏它们来换取成功。
- **完成或激活条件**：构型误差及相对变化速度满足目标，并持续规定时间。
- **失败与并发**：目标不可达、保护关系将被破坏、观测失效或超时均不算成功。与 MOVE_EE 或其他构型目标并发需要资源和目标兼容性检查。

### MAKE_CONTACT

- **操作数**：执行参与者、源区域、目标区域、待建立接触集合、允许的接近范围、接触判据及连续满足时间。
- **前置条件**：接近范围和目标区域已确定，局部接近受支持，目标状态可观测，要求保留的接触有效。
- **允许变化**：在限定范围内调整末端或内部构型，建立指定接触。远距离接近、重新选择目标和任务级搜索由程序安排。
- **持续约束**：保护指定的已有接触，限制目标物体位移、接触载荷和未许可交互。多接触目标可以逐步形成，但中间过程也必须满足约束。
- **完成或激活条件**：所有要求建立的接触满足各自的几何或感知判据，并持续规定时间。返回接触句柄和证据。
- **失败与并发**：错误区域接触、保护接触丢失、目标运动超限或超时均失败。建立新接触时，与现有 MAINTAIN_GRASP 的保护要求共同求解；接触成功不产生抓持成立证明。

### ESTABLISH_GRASP

- **操作数**：目标对象、已有 ContactSet、所需负载范围、允许相对运动、允许的构型与接触力调整，以及证据要求。
- **前置条件**：指定接触已经成立，负载要求和参考系明确；实现具有验证该抓持条件所需的模型或观测能力。
- **允许变化**：在已有接触集合内，调整预紧、内部构型和允许的接触位置，使抓持条件成立。需要新增或解除接触时返回需要外部重组的结果。
- **持续约束**：保持声明的接触成员和允许接触行为，遵守载荷、形变及对象运动限值，保留列出的外部支撑。
- **完成或激活条件**：在所声明模型和证据范围内，指定接触集合能够满足所需负载条件，且规定的稳定性指标持续成立。返回 GraspRelation、有效范围和证据。
- **失败与并发**：接触存在但承载不足、证据不足、调整范围耗尽或超时均不能成功。与运动或已有维护模式并发需要统一的负载目标；进入 MAINTAIN_GRASP 的控制移交遵循公共规则。

### MAINTAIN_GRASP

- **操作数**：有效 GraspRelation、维护时间或停止条件、允许调整范围，以及与其他动作共享的负载要求。
- **前置条件**：抓持关系当前有效，控制权可以接管，所需负载和后续运动相容。
- **允许变化**：在原有关系和限值内调整构型、预紧和接触力，补偿允许范围内的扰动。恢复动作不能隐式重组接触集合。
- **持续约束**：抓持条件、允许相对运动、滑移或滚动范围、接触成员、负载和执行限值持续成立。是否限制物体相对某个末端的位姿，由具体关系明确指定。
- **完成或激活条件**：接管控制后关系有效，进入 ACTIVE；按照公共规则持续执行至正常结束、取消或失败。维持抓持本身不固定物体的世界位姿。
- **失败与并发**：抓持有效性丢失、必要证据失效或负载超出范围时报告失败及有效的剩余关系。可与 MOVE_OBJECT、HOLD_OBJECT 和 APPLY_WRENCH 协调执行；不能同时坚持与这些目标冲突的固定力或位姿目标。

### BREAK_CONTACT

- **操作数**：待解除 ContactSet、受控参与者、允许的分离动作范围、几何间隙或等价无接触证据、连续满足时间。
- **前置条件**：待解除关系可识别；执行者有可行的分离方式。程序要求保持的抓持或承载关系已经适配新的接触集合。
- **允许变化**：在限定范围内调整构型或末端，使指定接触消失。修改软件中的关系记录不能代替物理分离。
- **持续约束**：保护其余指定接触、物体运动界限和仍然有效的承载义务。承载迁移需要由程序预先完成或显式安排。
- **完成或激活条件**：指定接触均已解除，并达到规定间隙或等价的已声明判据，持续规定时间。接触力读数为零不足以单独证明物理分离。
- **失败与并发**：残留接触、非目标接触被破坏、支撑义务冲突或超时均失败。与要求保留同一接触的 MAINTAIN_GRASP 冲突时，必须先显式更新或移交关系。

### MOVE_EE

- **操作数**：末端 Frame、执行参与者、目标位姿或轨迹、参考系绑定、受控方向、容差和运动范围。
- **前置条件**：末端状态可观测，所需运动受支持，初始交互状态与请求一致，已有控制目标可以协调。
- **允许变化**：执行目标所需的末端运动和内部配置调整；所有变化受指定路径、交互和资源约束限制。
- **持续约束**：保持所声明的接触、抓持和物体状态条件，满足运动与力学限值；不能用破坏受保护关系的路径达成目标。
- **完成或激活条件**：实际末端在指定受控方向完成目标或轨迹，并满足末端误差、相对速度和连续满足时间。
- **失败与并发**：目标不可达、轨迹或关系约束违反、观测失效或超时均失败。它的完成证据仅针对末端；与 MOVE_OBJECT 并发时必须约束相容。

### MOVE_OBJECT

- **操作数**：目标对象或部件的 Frame、参与者集合、已有交互关系、目标位姿或轨迹、参考系绑定、受控方向和容差。
- **前置条件**：目标对象状态可观测或可按声明误差界估计；已有交互关系能够实现所请求运动。抓持、推移等接触实现须由能力描述明确支持。
- **允许变化**：通过指定交互关系协调参与者，改变对象空间状态；允许的接触点变化受接触行为和区域限制。
- **持续约束**：保持程序要求的交互、抓持和负载条件，满足对象轨迹及各参与者限值。需要换接触或交接承载时请求外部程序处理。
- **完成或激活条件**：实际对象在受控方向完成目标或轨迹，并满足对象误差、相对速度和连续满足时间。
- **失败与并发**：末端达到目标但物体没有达到时仍失败。对象状态未知、交互不可行、约束违反或超时均不能成功。可与相容的 MAINTAIN_GRASP 协调；不默认要求所有对象运动都先形成抓持。

### HOLD_OBJECT

- **操作数**：对象或部件 Frame、执行参与者、已有交互关系、参考系绑定、目标位姿、受控方向、容差及允许恢复范围。
- **前置条件**：对象已经位于保持容差内，或位于显式给出的有界捕获范围；捕获和保持均具有可行控制方式。
- **允许变化**：通过已有交互关系补偿扰动，使指定位姿分量保持或返回容差。首次较大范围搬运由 MOVE_OBJECT 表达。
- **持续约束**：ACTIVE 期间目标位姿分量持续在容差内，并遵守所需接触、承载和力学约束。未受控方向仍受其他声明的公共限值约束。
- **完成或激活条件**：捕获完成且保持条件连续成立规定时间后进入 ACTIVE；其后按持续模式规则执行。
- **失败与并发**：ACTIVE 后超过硬容差即构成契约违反；有界恢复不抹去已发生的违反。可对不同部件或相容自由度并发操作；同一受控方向上的移动目标与保持目标冲突。

### APPLY_WRENCH

- **操作数**：施力参与者、受力对象、指定交互接口或接触组、表达坐标系、力矩参考点、六维力与力矩目标、受控方向、变化率和终止条件。
- **前置条件**：所需接触存在，接口具备产生所请求力的能力，测量或估计的对象和误差范围明确。
- **允许变化**：通过限定的构型与运动调整实现目标接口的作用力和力矩。指令不自动建立新接触。
- **持续约束**：保持所声明接触、抓持和对象运动范围，遵守各接触及执行资源限值。力的正方向规定为参与者通过指定接口作用在受力对象上。
- **完成或激活条件**：接口力与力矩在受控方向达到目标并持续规定时间后进入 ACTIVE，随后持续跟踪至正常结束、取消或失败。
- **失败与并发**：失去必要接触、载荷无法达到、观测失效或约束冲突均不能成功。接口合力为零不意味着各接触力为零；需要内部力分配时必须指定更细的接口目标。与运动并发必须明确相容的方向或协调规则。

### TRANSFER_SUPPORT

- **操作数**：目标对象、已有来源及目标 SupportSet、执行参与者、共同参考系与力矩参考点、各具名支撑的目标力和力矩区间、整体负载要求与允许对象运动。
- **前置条件**：相关接触已经成立；目标支撑在声明条件下能够满足接管要求；现有维护模式允许分配变化，承载状态具有足够观测或估计证据。
- **允许变化**：在限定范围内调整接触力、构型和必要的小幅运动，使承载分配连续改变。被动环境支撑只能通过可行的物理交互改变载荷。
- **持续约束**：整体承载要求、接触成员和允许对象运动持续成立，各来源卸载与目标加载须协调。整体要求须计入声明的动态作用。
- **完成或激活条件**：实际分配进入目标区间并持续规定时间，返回各支撑承载证据。若目标包含后续移除来源支撑，还必须验证剩余支撑独立满足所需负载条件；接触存在或来源当前载荷为零均不足以证明这一点。
- **失败与并发**：目标支撑承载不足、来源未卸载、对象偏移超限、分配不可观测或超时均不能成功。完成后通过公共控制移交规则延续新的分配；接触解除由 BREAK_CONTACT 显式执行。

## 返回结果与失败原因

结果至少包含 operation_id、生命周期状态、各目标和约束的三值判断、达成状态及时间戳、证据与假设、有效的接触和关系、仍在运行的控制句柄、实际发生的物理变化，以及具体失败原因。

建议使用下列语义原因族，具体编码格式后续冻结：

| 原因族 | 含义 |
| --- | --- |
| INVALID_REQUEST | 引用、单位、参考系、目标或契约不完整 |
| UNSUPPORTED_CAPABILITY | 实现不支持该操作所需能力 |
| PRECONDITION_UNSATISFIED | 前置条件被证据判定不成立 |
| EVIDENCE_UNAVAILABLE | 必要证据缺失、过期或精度不足 |
| INFEASIBLE_GOAL | 所声明模型及约束下目标不可行 |
| RESOURCE_OR_GOAL_CONFLICT | 控制资源或物理目标无法协调 |
| CONTACT_LOST | 要求保留的接触失效 |
| GRASP_INVALID | 抓持关系不再满足要求 |
| SUPPORT_INSUFFICIENT | 承载或接管条件不足 |
| CONSTRAINT_VIOLATION | 其他持续约束被违反 |
| TIMEOUT | 时限内未完成或未激活 |

失败原因可以并列出现，并保留首个相关时间。指令局部成功不自动等于任务整体成功；程序和基准仍需检查全过程约束及最终任务条件。

## 组合规则示例

以下是纸面语义示例，不能据此声称控制器或基准已经通过验证。

### 接近与搬运

SHAPE_HAND 和 MOVE_EE 在允许并发时分别准备内部构型和末端位置；MAKE_CONTACT 建立接触；ESTABLISH_GRASP 验证所需抓持；控制权移交到 MAINTAIN_GRASP 并确认 ACTIVE 后执行 MOVE_OBJECT。到达后的保持需求用 HOLD_OBJECT 和明确的控制移交表达。

搬运的动态负载必须处于抓持条件范围内；MOVE_OBJECT 成功使用对象状态证据。

### 承载交接

来源维持当前承载；目标通过 MAKE_CONTACT 加入接触。程序验证联合抓持或支撑条件，并将维护目标更新为允许承载转移的契约，然后执行 TRANSFER_SUPPORT。

若随后需要移除来源，目标接管的证据必须覆盖移除来源后的独立承载条件。新的承载分配和维护目标完成控制移交后，更新关系范围，再用 BREAK_CONTACT 解除来源接触。来源接触解除期间，目标承载仍然受到维护。

### 扶持与操作

对需要稳定的对象或部件执行 HOLD_OBJECT；另一组参与者对被操作部件执行 MOVE_EE、MOVE_OBJECT 或 APPLY_WRENCH。共同检查两者之间的机构约束和反作用负载。

只需要固定部分方向时明确选择受控方向。将同一自由度同时要求固定和移动会被判为冲突。

### 接触滑动

MAKE_CONTACT 建立指定接触；在共同执行层中组合切向 MOVE_EE 与法向 APPLY_WRENCH，持续约束接触区域和载荷。该程序不要求先建立抓持，也不需要新增 SLIDE 操作码。

### 局部换接触

在剩余接触能够承担负载的前提下，先调整维护范围和承载分配，再 BREAK_CONTACT 解除指定接触。MOVE_EE 或 SHAPE_HAND 完成允许的调整后，MAKE_CONTACT 建立新接触，再更新抓持关系。

如果剩余关系无法满足负载要求，程序需要额外支撑或其他策略；本草案不宣称每个换接触任务都可行。

## 待实验决定的边界

ESTABLISH_GRASP 与 MAINTAIN_GRASP 分别表达达到条件和持续维持条件；MOVE_OBJECT 与 HOLD_OBJECT 采用相同的生命周期区分。两组都可以在未来评估是否统一为“目标加生命周期”的形式，避免只合并其中一组而保留不一致的设计原则。

MOVE_EE 与 MOVE_OBJECT 目前用不同操作码显式区分控制对象和成功证据。可以研究统一的 MOVE 加目标类型方案；判据应包括契约清晰度、适配复杂度和错误率，而不能只比较操作码数量。

TRANSFER_SUPPORT 进入基础集的条件尚未满足。需要比较独立指令与较低层力控制加公共协调协议的组合，检查后者是否能够保持同样的全程约束、观测和切换语义。

所有持续模式都需要实现有界调整和明确退出。通用性指共享语义及能力发现；不表示每个实体或执行器都能实现全部操作。
