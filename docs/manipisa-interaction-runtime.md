# 六条指令的接触执行层

六个操作码都已连接到 Runtime → IsaacLabAdapter → 物理控制/观测。ISA 中仍然只出现角色、接触关系、参考系和目标；机器人关节、碰撞几何、材料与 PhysX 路径保留在 Adapter 绑定中。没有新增 Safety / Capability 模块，也没有接入 TacMap。

## 四条新增指令

| 指令 | 准入和动作 | 成功证据 | 执行中拒绝继续的情况 |
| --- | --- | --- | --- |
| MAKE_CONTACT | 接触对已绑定；每个参与者声明 BoundedMotion，使用局部位姿或构型目标 | 所有指定接触物理存在，法向力在阈值内，持续 dwell_s | 力超限、禁止区域接触、保护接触丢失、越出局部范围、观测失效、超时 |
| BREAK_CONTACT | 使用同一资源集合显式接管；声明允许的分离动作 | 接触消失，且保守几何间隙达到 separation_m，持续 dwell_s | 几何证据未知、残留接触、保护关系破坏、范围越限、超时 |
| CONTROL_GRASP | 指定接触必须已存在；仅在这些接触内执行有界调整；可要求进入时抓持已有效 | 接触力、相对速度、相对位姿范围和指定负载工况同时满足；返回 GraspRelation | 接触丢失、漂移、证据失效；ACTIVE 期间负载条件丢失后终止，不重抓 |
| APPLY_WRENCH | 接触预先成立；一侧臂的有界位置导纳；SUSTAIN | 接口在明确参考系与力矩参考点上的实际力/力矩满足所选方向容差，激活后维持至结束 | 接触丢失、力超限、导纳动作范围耗尽、反馈失效或激活超时 |

ContactGoal / GraspGoal 中每个参与者恰好对应一个 BoundedMotion。当前接触范围名为 `bounded_contact`；普通 MOVE / SHAPE_HAND 继续使用 `free_space`。上层声明 `protected_contacts` 与 `forbidden_contacts`，监测只覆盖已绑定接触对；它不自动推断全场景所有碰撞。

MAKE_CONTACT 不产生抓持证书。BREAK_CONTACT 不能用零力代替间隙，也不隐式转移承载。CONTROL_GRASP 不新增或重建接触。APPLY_WRENCH 不自动接近物体。未知观测不能计入连续成功时间。

## 结构化接触观测

`StateSnapshot.contacts` 以接触 ID 为键，包含参与角色、目标、时间、有效性、接触存在、法向力、作用于目标的合力、相对世界原点的力矩、法向接触点和几何间隙。`valid` 与 `wrench_valid` 分开：只有法向报告时可以检测接触，但不能认证完整接口力。

`PhysXContactSource` 每对绑定一个实际传感刚体与目标刚体。接触报告须在仿真 reset 前启用；接触源在 reset 后创建。每个物理步缓存一次；异常、缓冲区容量到达上限、原始法向数据与聚合值不一致都显式使证据无效。

合力/力矩分别累计法向接触点和摩擦作用点。方向统一为参与者作用在目标上。先将世界原点力矩平移到请求的参考点，再旋转到请求坐标系。该路径使用 PhysX 原始 patch 数据，不把平均接触位置乘合力冒充完整力矩；接口依据 [NVIDIA PhysX Tensor API](https://docs.omniverse.nvidia.com/kit/docs/omni_physics/107.3/extensions/runtime/source/omni.physics.tensors/docs/api/python.html)。

分离证据由绑定提供实时碰撞几何间隙。已有球体间隙、包围实际碰撞体的世界 AABB 间隙工具。AABB 正间隙能证明分离，AABB 重叠本身不能证明接触。不要用视觉网格或陈旧几何当作碰撞体间隙。

## 抓持证书的范围

当前 GraspGoal 必须给出作用对象、相对参考系、有限个非零六维外载工况，以及摩擦系数。外载以世界轴表达，力矩参考点为对象原点。Adapter 配置的 `friction_lower_bound` 是可信的保守校准值，请求不能通过增大摩擦系数制造承载能力。

求解器以实际接触点、法向和当前法向预紧力建立内接摩擦棱锥，检查每个明确外载工况是否存在力与力矩平衡。各接触的法向预算不超过实际观测预紧。这样保留了“能承担某个工况”与“当前正在承担该载荷”的区别。

模型假设刚性点接触、准静态载荷、保守 Coulomb 摩擦系数，以及接触间能够在预紧预算内重分配载荷。它没有证明任意动态负载、执行器余量或通用力闭合。GraspRelation 返回这些适用条件、接触成员与验证时刻；每个 ACTIVE 物理步重新验证，结束后历史证书不代表仍在持续保证抓持。需要动态承载的任务应增加相应模型与带时效证据。

## 施力控制与接管

位置导纳将所选方向的力误差积累成局部位姿修正，再通过已有 Jacobian/IK 和位置驱动执行。修正受速度、总位移和转角边界约束。接管时从保留的关节命令重建已有 PD 偏置，避免把目标重置成实测位置而突然卸掉预紧。物体上的力仍来自物理接触，指令实现不通过对物体写入外力来伪造施力。

这条实现不依赖 Isaac Lab OSC 的三维力反馈限制。六维观测与所选方向控制路径已经连接，但实际可控方向仍由机器人 Jacobian 和接触几何决定；不可达请求超时或在局部边界处失败。独立六轴力矩控制的机器人任务还需要专门物理验证。

终态的 HOLD_POSITION 在接触路径保留最后的有界位置目标及所有权；没有继续积分导纳，也不继续宣称原力/抓持目标成立。取消不会主动张手。需要分离时提交 BREAK_CONTACT 并显式接管相同资源集合。

## 并发与更新

资源锁包含实际关节与规范化物理接触对，耦合锁使用目标刚体路径。更换显示名称不能绕过同一资源的互斥。不同指令作用同一目标刚体时当前保守拒绝并发；一条指令可以声明多个参与者统一输出目标。接触指令仍检查 ActorBinding 中显式声明的其他耦合组。场景绑定负责声明跨关节组的机械/任务耦合。

本版不支持接触指令运行中任意改目标或接触成员。使用新调用和显式接管，失败的接管保留旧句柄。与对象运动的协调控制、通用闭链求解、跨资源集合移交及完整 TRANSFER_SUPPORT 程序不属于这次完成范围。

## 接入顺序

1. 创建 Isaac Lab 场景，并在目标刚体启用接触报告。
2. reset 后创建 PhysXContactSource，绑定角色、真实刚体对、实时几何间隙；抓持场景提供摩擦校准下界。
3. 用 `IsaacLabAdapter(..., contact_source=source, entities=...)` 接入对象状态与接触源；关节与控制参考系由 ActorBinding 解析。
4. 提交带显式接触目标的六条 ISA 指令，由同一 Runtime.step 推进；RGB 通道可独立开启。

完整可运行示例见 [物理接触验收入口](../examples/isaaclab_interaction_smoke.py)，测试见 [接触契约测试](../tests/test_interactions.py)。该验收使用双指夹持自由物体和单轴施力探头，不等同于 Wuji 灵巧抓持或 Bench2Dex 完整任务成功率。
