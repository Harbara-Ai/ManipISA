# ManipISA 与 Direct 的 Bench2Dex 对照方案

论文层面的主实验、Agent 候选、消融与预算规模见 [CVPR 主实验设计](cvpr-main-experiment-design.md)。本文件保留指标采集口径。

本方案在每个 Agent 内比较 ManipISA 和原生 SDK Direct 两种接口。评测任务、成功判定与扰动协议沿用 Bench2Dex；本轮仅确定指标及其采集口径，不增加任务或契约测试。保留 SR、LSCR、SafeSR、平均成功仿真耗时，以及 Native tokens、墙钟时间和模型调用次数七项原始指标；另按 [总评分规范](manipisa-overall-scoring.md) 计算每个模型 Direct／ManipISA 的 Overall：完成程度 30%、执行可靠性 30%、成本效率 40%；成本内部墙钟、token、模型请求权重为 5∶4∶1。

核对日期为 2026 年 10 月 3 日。本地 Bench2Dex 工作树干净，提交为 fd90dcc625b66c2e535a8b25bcf75bc81c7b080d，指标版本为 core-v1.8-policy-step-query-split。尚未运行对照实验。

配套文档：[六条核心契约草案](manipisa-v0.2-core-contracts.md)和[语义保留验证](manipisa-v0.2-semantic-preservation.md)。

## 官方指标及解释

下表依据本地 benchmark/metrics.py 的 FIELD_SEMANTICS、core_metrics 和 metric_tracker.py 的实际计算，含义与论文评测附录相核对。

| 指标 | 定义 | 使用方式 |
| --- | --- | --- |
| SR | 稳定成功回合数除以全部评测回合数 | 主指标；默认终态谓词持续成立 0.5 s |
| LSCR | 每回合曾经完成且满足依赖的阶段比例，再对回合平均 | 包含失败回合的过程进度 |
| 平均成功耗时 | 成功回合达到稳定成功的平均仿真秒数 | 必须同时报告 SR 和成功样本数 |
| SafeSR | 成功且没有配置中的硬违规的回合比例 | 分母是全部回合 |
| HVR | 发生过硬违规的回合比例 | 默认包括配置中的掉落和物体高速事件 |
| DropR 和 HSR | 掉落回合比例和被跟踪物体高速回合比例 | 两种事件可能重叠 |
| VSR_step | 全部执行物理步中发生任务违规的步数比例 | 与回合级违规率一起解释 |
| 分通道 SR 和 RR | 各扰动通道成功率，以及相对 None 的成功率比值 | None 成功率为零时 RR 未定义 |

reach-and-stop 在稳定成功时停止；失败、超时和已经开始评测后的策略或运行错误保留在分母。fixed-horizon 是另一种协议，不混入同一主表。

辅助诊断包括瞬时与终止时成功、当前阶段进度、物理步数、控制步数、策略查询数、关节界限及饱和、运动学抓持稳定性代理 GSI、工具选择和切换、关节运动平滑性。缺失或不适用的量记为 N/A。

官方高速事件是运动强度代理，不是接触力或碰撞测量；GSI 也不是力闭合、接触集合正确或独立承载的证明。

## 效率统计的口径差异

项目网页将展示的 Eff. 定义为专家平均完成步数除以成功策略回合的合并平均完成步数。本地代码先计算每个成功回合的 expert_time_s / time_to_stable_success_s，再对回合比值取平均。平均比值与平均耗时的比值通常不同。

因此，主表优先使用 avg_time_to_success_s。若复现网页 Eff.，使用网页说明的聚合方法和物理步单位，并另命名；若保留代码 task_efficiency，则明确这是成功回合比值的均值。零成功时都记为 N/A，不能写成零效率或最佳耗时。

## 对照组

主实验只设 ManipISA 和 Direct 两组。Direct 的定义是 Agent 直接使用机器人或仿真环境的原生 SDK 与通用开发工具完成任务，不预先加载 ManipISA 指令接口、技能文档或现成语义操作程序。

| 组别 | 执行路径 | 可用能力 |
| --- | --- | --- |
| Direct | 自然语言任务到 Agent，再到自行编写或调用的 SDK 控制程序 | 原生 SDK、接口文档、通用工具和双方共享的基础资源；允许自主编写脚本和处理反馈 |
| ManipISA | 相同任务到 Agent，再到 ManipISA 指令和运行时，最后通过底层 SDK 执行 | 相同基础资源，加已提供的通用指令契约和运行时 |

每个 Agent 的两组使用同一 Agent 版本、模型版本、推理配置、任务信息、观测权限和上下文管理规则。原生 SDK 已提供的关节控制、末端位姿控制、IK 或力控能力可供 Direct 正常使用，不人为删减。接口、文档和可调用库的版本及权限在正式测试前冻结。

Agent 自行写代码、调用已有 SDK、计算中间目标或构造任务脚本，均可属于 Direct。其阅读接口、生成代码、调试、查询、失败和重试的 token 与耗时全部计入成本；不能预先提供 ManipISA 的任务程序，再将其调用记作 Direct。两组采用相同的回合隔离或记忆规则。

Joint 和笛卡尔空间控制描述 SDK 操作目标的层级，不再作为实验分组。发送关节角目标是关节级接口；发送末端位置与姿态是笛卡尔空间接口。即使 SDK 内部再将末端位姿转成关节命令，对 Agent 暴露的仍是位姿接口。同一 Direct 程序可以混合这些调用。

这个主实验评估提供 ManipISA 指令及其运行时对 Agent 完成任务的整体收益，包含其闭环维护、协调及工程实现。它不能单独证明收益只来自指令名称或语法。当前不额外拆分 Direct 子组；后续需要研究具体机制时再另行设计消融。

所有调用使用相同物理时间和计算预算规则。Direct 可以提交动作片段或运行闭环脚本，不要求它逐个物理步向模型请求动作；双方具有一致的基础反馈权限。ManipISA 内部控制和实际模型调用同样记录。

ACT、DP 等已训练策略可作为外部参照，与上述两组分表报告，不将不同训练或感知条件的比较解释为接口差异。

## 观测与数据隔离

当前实现阶段先运行结构化反馈，再开启可选 RGB 回传；触觉本期不接入。两种配置共用 Runtime、状态来源和成功判据。RGB 回传只增加 Agent 的图像观察，不自动意味着底层已改为视觉状态估计。若结构化状态含仿真真值，应标为特权状态条件下的视觉补充实验。代码接入说明见 [Runtime](../README.md)。

观测类型遵循实际采用的 Bench2Dex 协议。若使用结构化状态，两组得到相同权限范围内的关节、末端、物体、几何、接触估计和能力信息。仿真真值可供该轨道共同使用，并明确标为特权状态实验。只有执行器内部可见的物理量也必须审计，避免 ManipISA 的内部控制器独享另一组无法利用的状态或模型。

若使用视觉或视觉加触觉，两组使用相同传感输入与共享状态估计。评价器可保留真值，但不得通过状态工具或错误反馈泄漏给某一组。两种观测轨道分别统计。

示范可用于离线检查任务可行性、开发控制器及预先约定的训练。正式回合只读取允许的初始化与当前观测，不读取该回合未来动作、物体状态或阶段标签。None 与示范锚点的重合须披露，不把匹配锚点结果称为未见初态泛化。

官方评价器只负责独立评分。在线任务信息和阶段反馈权限在组间一致；各组不能根据官方隐藏成功位修正自己报告的指令成功。

## 通道与配对

| 通道 | 官方变化因素 | 指标解释 |
| --- | --- | --- |
| None | 恢复匹配锚点 | 基础执行能力 |
| Equi. | 物体初始位姿和桌高 | 几何变化下的适应能力 |
| Inv. | 背景、桌面材质、光照、干扰物和相机等视觉条件 | 主要用于感知轨道 |
| Full | 两组因素同时重新采样，独立于锚点 | 完整场景扰动 |

None、Equi. 和 Inv. 按官方锚点关系组织；Full 不与其他通道假装构成锚点配对。但同一个 Full 样本可以在两种方法之间恢复，用于方法间配对比较。

方法间配对同时冻结初始化状态、场景采样结果、机器人和资产配置、随机化参数及评价阈值；仅使用相同 seed 名称不足以保证场景相同。确认可恢复的状态一致性后记录状态摘要和配置散列。

结构化真值不受视觉扰动的轨道，Inv. 成绩不能解释为视觉鲁棒性。如果干扰物会产生碰撞，其物理影响需另行说明。

## 官方预算口径参考

下面保留此前核对的 UR5 与 Wuji 两个原生任务预算作为口径示例，不据此限定正式任务范围。正式任务与协议按 Bench2Dex 配置执行；指令规范保持通用。

| 任务 | 专家参考物理步数 | 默认预算物理步数 | 对应控制步数 | 60 Hz 下的预算秒数 |
| --- | --- | --- | --- | --- |
| 21_condiment_box_loading | 1654 | 2481 | 827 | 41.35 |
| 27_ball_box_loading | 2380 | 3570 | 1190 | 59.50 |

预算由 script/eval_budget.sh 的默认专家步数乘 1.5、再向上对齐 3 个物理步推导，无覆盖参数时成立。实际启动必须记录解析后的预算与 dt，不能直接套用 run_policy.py 的 400 控制步默认值或指标模块的 1200 物理步默认值。

物理、控制和评价器时间轴在组间一致。评价器逐物理步独立运行，不能等一条长指令返回后才检查成功或违规；稳定成功时按同一规则结束评分。模型推理等待是否暂停仿真也必须一致并记录；首轮建议统一使用同步推进，再另测实时部署延迟。

本轮不确定任务子集、额外观测轨道或样本数量。各 Agent 内的 Direct 与 ManipISA 使用相同的资源预算规则，正式运行前冻结。跨模型不以相同 token 数直接代表相同计算资源。不能用“相同指令调用次数”替代相同物理时间和资源预算，因为一次指令可覆盖不同执行时长。

## 多 Agent 的统一效率统计

Agent 是执行任务的软件系统，底层模型是另一个配置维度。Codex 只是一个可接入的 Agent；其他 Agent 通过各自适配器提供原生用量和模型请求事件。记录 Agent 名称与版本、模型提供方与版本、推理配置和接口组别；一次回合涉及多个模型时保留各模型明细。

| 实验单元 | Direct | ManipISA |
| --- | --- | --- |
| Agent A 与固定模型配置 | 原生 SDK 路径 | 指令与运行时路径 |
| Agent B 与固定模型配置 | 原生 SDK 路径 | 指令与运行时路径 |
| 后续 Agent | 同样接入 | 同样接入 |

主要结论来自每一行内部的配对比较。不同 Agent 或模型之间的绝对表现可以展示，但不能将其差异全部归因于 ManipISA。

| 指标 | 统一采集口径 | 数据来源 |
| --- | --- | --- |
| Native tokens | 汇总回合内实际模型请求的原生用量，保留输入、输出和提供方总量；缓存与推理 token 按原始定义保留，属于子集时不重复相加 | Agent 适配器读取模型响应、官方事件或可核验日志 |
| 墙钟时间 | 环境就绪并交付任务时开始，直到该回合触发统一终止条件；包含模型等待、工具执行、运行中编译与调试、控制和重试 | 公共实验运行器的单调时钟 |
| 模型调用次数 | 回合内实际发起的推理请求数；记录完成、失败和重试状态，重试请求另计 | Agent 适配器采集请求发起与结束事件 |

三项指标都在实验运行过程中自动采集，结束后统一汇总。它们可以与 Isaac Lab 集成在同一个实验入口，但职责分开：Bench2Dex／Isaac Lab 提供任务结果和仿真时间，Agent 适配器提供模型遥测，公共运行器负责回合边界、计时和关联。不把模型用量计量嵌入物理步循环。

墙钟主指标包括失败和超时回合。环境预加载、回合前 reset、实验外人工等待及终止后的报告整理单独记录，不混入主指标；回合内读取接口文档和自主恢复计入。仿真等待模型时是否暂停须组间一致。并行请求或工具执行的耗时可能重叠，不能把各段耗时相加当作墙钟时间。

模型请求数、Agent 工具调用数和 Bench2Dex 的 policy_query_count 分别记录；一次策略查询可能触发多个模型请求，一次模型请求也可能发出多个工具调用。轮询、流式消息片段和连接预热不算新的推理请求。若 Agent 使用子 Agent 或辅助模型，其任务内请求也归入同一回合，并按调用来源保留明细。只暴露最终响应、无法观测内部请求的系统，应注明统计范围；不能把可见次数当作完整调用次数。

每条记录使用统一 episode_id，并关联任务、通道、初始化标识、Agent 配置和接口组别。用请求 ID 或事件序号去重，累计 usage 事件应取相应差值或最终值，不能把多次累计快照求和。保留原始记录与统计来源。未提供或无法核验的 token、调用次数记 N/A，同时报告计量有效回合数；计量缺失不等于零成本，也不自动删除其任务评分。

不同模型可能采用不同 tokenizer、计费和 usage 定义，因此 Native tokens 的主要比较是在相同 Agent／模型配置内看 Direct 与 ManipISA 的差异。跨模型分开列出，不把原生 token 总数当作统一计算量；跨模型回合保留分模型用量，不强行合成可比的 token 成本。

现有 DexISA evaluation 的原生 usage 解析、回合日志和耗时记录可作为复用起点；其旧任务、MuJoCo 场景及 Agent 提示约束不随计量模块迁入。Codex 原生事件解析作为一个适配器；已有代码中用工具事件数量近似模型决策次数的路径不能用于本指标。各适配器必须验证请求计数、失败与重试、usage 去重及回合归属。本节为设计，尚未实现多 Agent 采集器。

## 统计与审查

主表按 Agent／模型配置、任务、通道和接口组别列出 Overall 及其三项组成，同时列出 SR、SafeSR、LSCR、平均成功仿真耗时，以及包含失败回合的平均 Native tokens、模型调用次数和墙钟时间。计量完整时使用全部正式回合，计量缺失时明确有效样本与覆盖率，不用零补齐。另列样本数、成功数、失败数及基础设施或计量异常数作为解释信息；官方其他诊断量按需附表。同时给出配对 SR 差值及其 95% 置信区间；跨任务汇总对任务等权，保留任务级结果。

置信区间在同一任务和通道内按配对场景重采样；若同一锚点有多次模型采样，按锚点聚类，不能把相关重复当成独立场景。有限任务上的区间不支持全任务分布泛化；环境样本也不能替代对模型随机性的重复测量。

成功耗时以各组成功集合统计时存在选择差异，必须配合 SR；双方共同成功的配对子集可作为补充。主要终点和停止规则在看正式结果前冻结。运行错误保留在主分母，另外报告错误类型与可用性。

发现的配置注意事项：任务 21 的自然语言描述、阶段依赖和最终成功谓词并不完全相同；最终谓词不核验所有文字中的左右手分工或移动箱子到桌面中心要求。本轮按官方定义评分，不增加语言遵循指标或强化成功判定。

重试采用事先冻结的规则，保留首次错误和全部成本；不能只保留重试后成功的结果。策略内部恢复继续消耗同一回合预算，外部重开回合需另记。

所有实验保存完整请求、观测权限、底层动作、物理时钟、模型查询、token、评价轨迹、拒绝和错误记录。运行前核对任务可行性，不能因某方法失败而事后删除难例。
