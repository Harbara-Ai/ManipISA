# ManipISA 总评分标准

实施更新（2026-10-05）：[评分函数](../../manipisa/evaluation/scoring.py) 已实现。开发评测共同参考值为 T_ref=600 秒、U_ref=200,000 native tokens、K_ref=30 次，见 [开发运行说明](ur5-wuji-development-benchmark.md)。这些归一化参考值与物理／墙钟停止上限分开；当前 1200 秒停止上限不改变 T_ref。下文保留设计推导，“尚未实现”和“参考值待定”描述原稿状态。

2026 年 10 月 4 日，v0.1 设计稿。评分对象是固定模型及 Agent 配置下的 Direct 或 ManipISA 执行接口，每个配置独立得到 0～100 分。任务、初始化、扰动与底层任务评价复用 Bench2Dex；成本采集参考 DexISA evaluation。本文件是评分规范，不表示评分器已实现或实验已运行。

用户已确定三项一级权重：任务完成程度 30%、执行可靠性 30%、成本效率 40%。成本内部墙钟时间、Native tokens、实际模型调用次数按 5∶4∶1 分配。通用性不进入分数；美元费用和成功仿真耗时单独报告。本稿采用下述默认合成规则，并明确区分官方判定与本项目合成，避免将自定义 Overall 称为 Bench2Dex 官方指标。

## 总体公式

对回合 i，所有组成分先转为 0～1：

Overall_i = 100 × (0.30 A_i + 0.30 R_i + 0.40 C_i)

| 组成项 | 定义 | 最高贡献 |
| --- | --- | ---: |
| A_i，任务完成程度 | 官方成功与阶段进度按本稿规则合成 | 30 分 |
| R_i，执行可靠性 | 官方安全成功标志，即最终成功且无官方硬违规 | 30 分 |
| C_i，有效成本效率 | 任务完成度 × 无违规标志 × 原始成本效率 | 40 分 |

其中 C_i = A_i × H_i × E_i，E_i = 0.50 e_T,i + 0.40 e_U,i + 0.10 e_K,i。完整公式为：

Overall_i = 30 A_i + 30 S_i H_i + 40 A_i H_i (0.50 e_T,i + 0.40 e_U,i + 0.10 e_K,i)

这里保留此前候选的原则：成本效率奖励必须与实际任务质量对应。成本门控是我们的合成设计，不是 Bench2Dex 官方规则。记录原始 E_i 和门控后 C_i 两列，不把 C_i 当作纯资源消耗量。对完整可靠成功，基础两项共 60 分，墙钟、token 和请求效率分别最多贡献 20、16、4 分。

本稿用 SafeSR 对应的回合标志作为可靠性分，而非单独的 1−HVR。没有违规但没有成功的回合不获得可靠性 30 分，避免静止不动获得高可靠性分。任务成功在 A 和 R 中各有贡献是此规则有意体现的偏好；R 不是与成功独立的安全指标，原始 HVR 仍须单独报告。

## 任务完成程度

取 Bench2Dex 的回合字段：S_i 为 stable_success，取 0 或 1；P_i 为 latched_stage_completion_rate，范围 0～1。只读取独立评价器，不使用 Agent 自述或 ManipISA 指令 SUCCEEDED 判断任务成功。沿用各任务实际终态、阶段依赖和持续成立时间，默认 dwell 为 0.5 秒不代表所有任务都固定为该值。

任务完成度采用默认候选：

A_i = S_i + (1−S_i) × λ × P_i，λ = 0.25

可靠性在下一项独立计算，这里不因违规直接清零 A_i。最终成功时 A_i=1；尚未成功时，官方阶段进度最多得到任务完成项的 25%，即最多 7.5 分。λ=0.25 是本项目的部分进度折扣，不是官方权重，也不是用户指定的一级权重；正式评测前需与归一化参考值一起冻结并做敏感性分析。

P_i 不使用 Agent 规划步骤数、完成的工具数或指令数。锁存阶段与依赖处理完全交给官方评价器；无阶段定义的任务不能自行补造阶段，必须在冻结任务配置时明确官方输出和可评分性。

## 执行可靠性

取官方 safety_hard_violation：出现过硬违规时 H_i=0，否则 H_i=1。定义：

R_i = S_i × H_i

同一单元内对 R_i 求平均就是官方 SafeSR 的回合平均形式。官方默认硬违规主要覆盖掉落和被跟踪物体高速，具体阈值及启用配置按冻结版本执行；关节限制、接触力、碰撞等不能未经声明自动加入。这是官方定义范围内的安全成功，不等于完整真实机器人安全认证。

本次将任务完成与可靠性拆成独立的 30 分后，旧版“任意硬违规使 Overall 全部归零”不再适用：违规会清零 R_i 和 C_i，仍保留任务完成项，最多 30 分。这样如实保留“完成了任务但执行存在违规”的区别。若以后需要违规即总分归零，应另立评分版本，不能暗中修改。

官方判定缺失或未知不能填成无违规；需标记评价无效。任务成功终止后不继续任意延长观察窗，也不允许方法自行提前截断，以避免选择有利的可靠性窗口。

## 原始成本效率与归一化

设 T_i 为墙钟秒数，U_i 为 Native tokens，K_i 为实际模型推理请求数。每项越少越好，分别计算：

e_T,i = 1−clip(T_i/T_ref, 0, 1)

e_U,i = 1−clip(U_i/U_ref, 0, 1)

e_K,i = 1−clip(K_i/K_ref, 0, 1)

E_i = 0.50 e_T,i + 0.40 e_U,i + 0.10 e_K,i

clip(x,0,1) 表示将 x 裁剪到 0～1。原始量须为有限非负数，否则该项无效；不得依靠裁剪掩盖负时间、负 token 等计量错误。三个参考值必须为有限正数，归一化参考值与实际停止上限分开保存。

参考值采用全配置共同的冻结尺度，不按 Direct 与 ManipISA 各自成绩归一化，也不以某组结果作为另一组分母。推荐校准流程：先冻结独立开发任务与初始化清单、各配置的相同采样数量和统一运行上限，取得全部模型与接口的完整开发成本记录；等权混合配置后，以各成本分布的第 95 百分位作为参考值候选，token 与请求次数向上取整。不得只保留成功回合或只选有利于某方法的记录。

开发阶段检查参考值的饱和比例及 0.5 倍、1 倍、2 倍尺度下的排序敏感性，再在正式测试前冻结评分版本。没有开发测量，本稿不虚构 T_ref、U_ref、K_ref 数值。新增模型继续沿用已有尺度；若重新校准则升级版本并用新尺度重算全部配置。测试分数不能用于挑选有利阈值。

原始 T、U、K 的均值和分布都包含失败及重试成本，即便该回合 C_i 为零也不能从成本报表删除。全回合 E_i 的平均只是纯效率诊断，正式成本项使用 mean(A_i H_i E_i)，不能替换成 mean(A_i) × mean(H_i) × mean(E_i)。

## 墙钟时间采集

采用同一宿主上的单调高分辨率计时器，如 time.perf_counter_ns。公共实验运行器在以下两个边界打点：

T_i = (episode_terminal_monotonic_ns − task_delivered_monotonic_ns) / 10^9

起点为环境和 Agent 进程准备好、目标任务和首批允许观测交付 Agent 的时刻。任务内容不得在此之前交付；任务专属文档阅读、上下文整理、生成代码和规划全部位于计时窗内。终点为独立评价器检测到官方稳定成功，或正式失败、超时、停止条件触发的时刻。

计入模型服务等待、请求重试与退避、工具和脚本执行、视觉读取、调试、仿真推进及回合内恢复。排除提前加载环境和模型、回合前 reset、实验外人工等待、终止后整理报告与资源回收。共享基础设施和进程冷启动另报，不能将任务专属工作移到起点之前。

不使用仿真时间替代墙钟，也不把推理耗时当成整个回合墙钟。推理、工具和物理计算可能嵌套或并行，各段耗时求和不能替代端到端包络。保留 T_agent、T_tool、T_sim_compute、T_physical_sim 作为诊断，明确其是否重叠。

固定或披露硬件、模型部署、并发额度、区域及网络条件；在同一模型内交错执行 Direct／ManipISA。仿真等待模型时是否暂停，两组一致并记录。模型采样不可用或服务故障不能通过事后减去等待时间美化墙钟。

## Native tokens 采集

主量为 U_i = sum_r native_total_tokens_r，其中 r 为归属此回合的全部实际推理请求及子 Agent 或辅助模型调用。保留输入、输出、缓存和 reasoning 明细及提供方原始 usage。

按 DexISA parse_usage 的原则，只使用提供方响应、原生 Agent 事件或可核验日志中的权威用量，不根据字符数、工具次数或本地 tokenizer 猜测 Native tokens。历史上下文、接口文档、图像和推理是否计入以及怎样归类，遵循提供方原生定义并记录。

cached_input_tokens 是输入子集时不再次相加；reasoning_tokens 是输出子集时不再次相加。不同提供方字段语义不同：只有确认字段互不重叠且覆盖总量后，才能从分项构造 native_total_tokens。缺失细分项不一定影响总量可用，但缺失总量且不能无歧义重建时 U_i 为未知，不能写零。

每条请求用 request_id 和 attempt_id 标识，响应按唯一记录去重。流式 usage 或线程累计快照只取最终量，或在明确边界上取累计差值；不能把累计快照逐条相加。失败或取消调用若已有用量也须计入；服务端可能已消耗但未返回用量时记录计量缺失。

回合终止后不再发起新的任务推理。终止前已经发起、终止后才返回的请求，整次实际用量仍归该回合；不能凭时间比例估算其终止前 token。计量收尾不延长任务墙钟，取消后返回的最终 usage 继续补入账本，结算完成前分数标为未结算。

不同模型的 tokenizer 和多模态计量不同，U_i 不是架构无关的计算量。主结果重点解释同一模型的 Direct／ManipISA 差值，跨模型总分注明原生计量条件并补充去掉 token 项的敏感性结果；不能把它称为统一 FLOPs。多模型 Agent 保留按模型分解的用量，跨 tokenizer 求和属于本规范声明的原生 token 计数约定。

## 模型调用次数采集

定义 K_i 为任务计时窗内实际发出的推理请求 attempt 数，包括任务内子 Agent 和辅助模型。请求发出时计数，不等响应成功后才计数。一次多模态输入仍是一条请求；一次响应触发多个工具也仍是一条模型请求。

有新推理请求的重试另计。传输层重新连接、轮询、流式消息片段、工具调用、仅本地缓存命中而未请求推理的操作不计。逻辑 request_id 相同的重试保留不同 attempt_id，不能被普通去重误删；重复上报的同一次 attempt 只计一次。

记录 completed、failed、canceled、in_flight 等状态。最终结算应满足 started = completed + failed + canceled，且 in_flight=0；无法核验的隐藏请求不伪装成精确次数。保留 tool_call_count 与 Bench2Dex policy_query_count，它们不替代 K_i。

真实请求数不可观测的 Agent 可以报告观测到的下界，但 K_i 的正式计量状态为不完整；不能用工具次数或 Agent 自称的思考轮数补齐。正式评分优先接入能够审计请求轨迹的 Agent。

DexISA 已提供的是参考实现，不是已经接入 Isaac Lab 的通用采集器。公共运行器负责墙钟和 episode_id，各 Agent 适配器负责原生 usage 与请求账本，Bench2Dex 负责物理任务轨迹和评价。

## 汇总与异常处理

对每个固定模型／Agent 配置和接口，先计算所有计划回合的 Overall_i，在每个任务—通道单元内平均，再对通道和任务等权平均。重复采样保留在初始化聚类内并取均值，不取最好一次。结果包括 Overall、A、R、C、原始 E、SR、SafeSR、LSCR、T、U、K、美元费用和计量覆盖率。

同模型 Direct／ManipISA 使用相同已保存初始化、任务定义、公共观测与归一化参考。报告绝对分及 ΔOverall、95% 配对置信区间；保留原始物理指标，不能只展示合成分。置信区间按初始化聚类重采样，重复和相关通道保持关联。任务通用性与跨 Agent 一致性是结果分析，不是额外加分。

失败、预算耗尽和策略错误均保留，不能只统计成功回合成本。基础设施在交付任务前无法启动的计划单元单列并按固定规则补齐；任务交付后发生的异常完整留痕，不能无成本重开直到成功。

S、P、H 或 T、U、K 任一必需字段未知时，Overall 为 N/A，不当成零或满分，不动态调整其他指标权重。真实数值为零和测量缺失分别表示。完整排名要求计划单元计量补齐；局部可用样本均值必须注明覆盖率，不与完整分数混排。缺失美元费用不影响新版 Overall。

成本参考值、执行上限、评分版本、官方评价器版本、硬违规配置、模型／Agent 版本和硬件设置都应进入冻结配置。参数变更后需升级评分版本并统一复算，不能只更新某一组。

## 算例与边界检查

以下为公式算例，不是机器人实验。设 e_T=0.8、e_U=0.6、e_K=0.5，则 E=0.69，λ=0.25。

| 回合情况 | A | R | C | Overall |
| --- | ---: | ---: | ---: | ---: |
| 成功且无违规 | 1 | 1 | 0.69 | 87.60 |
| 成功但有硬违规 | 1 | 0 | 0 | 30.00 |
| 未成功，阶段进度 80%，无违规 | 0.20 | 0 | 0.138 | 11.52 |
| 未成功，阶段进度 80%，有硬违规 | 0.20 | 0 | 0 | 6.00 |
| 无进展且无违规，即使资源消耗很少 | 0 | 0 | 0 | 0.00 |
| 任一必需计量缺失 | — | — | — | N/A |

完整可靠成功范围为 60～100 分；成功但有违规为 30 分；普通未成功且无违规最多 17.5 分；未成功且违规最多 7.5 分。由此可见在本稿 λ 下，部分进展不会超过完整任务成功，零进展也无法靠低成本刷分。

可靠成功时，效率分提高 0.1 对 Overall 的影响分别为：墙钟增加 2 分、token 增加 1.6 分、模型请求增加 0.4 分。资源已经超过参考值时该分项饱和为零，仍须报告原始消耗。
