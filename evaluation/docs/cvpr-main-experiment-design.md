# ManipISA 的 CVPR 主实验设计

2026 年 10 月 4 日设计稿。按 CVPR 2027 组织完整研究方案，再依据预算裁剪。本文规定建议采用的任务、Agent、评分、对照和证据边界；所有实验均为待执行设计。

核心建议是：用统一 Agent 循环下的四个视觉模型完成 Direct 与 ManipISA 的配对主实验，用原生 Codex 和 Claude Code 检验跨 Agent 系统适用性，并用共享控制器的机制实验检验精简接口与执行契约的贡献。任务、原生机器人绑定、扰动和成功判定全部来自 Bench2Dex，不新增任务。

现有 [评测口径](bench2dex-manipisa-direct-evaluation.md) 继续用于日志与指标；本稿补充论文实验矩阵。指令版本采用 [六条核心契约](../../docs/manipisa-v0.2-core-contracts.md)。以下模型名单、样本量、观测设计及消融均为本项目建议，不是 CVPR 或 Bench2Dex 的强制要求。

## 研究问题与可支持的结论

论文拟检验的命题是：将视觉语言 Agent 的操作意图表达为少量、可组合且带执行契约的物理指令，是否能在相同任务和资源条件下提高双臂灵巧操作成功率，并降低完成任务所需的模型交互成本。

| 研究问题 | 对应实验 | 结论边界 |
| --- | --- | --- |
| 完整系统是否有效 | 同一模型的 Direct 与 ManipISA 配对 | 检验指令、运行时和工程实现的整体效果 |
| 收益是否跨模型存在 | 固定 Agent 循环，四个模型分别配对 | 多模型适用性，不代表覆盖所有模型 |
| 收益是否跨 Agent 系统存在 | 原生 Codex、Claude Code 各自配对 | 跨软件系统适用性，不把两系统差异归因于 ISA |
| 收益是否来自精简表达和契约 | 相同底层控制器的接口与契约消融 | 分析机制；单纯击败弱 SDK 基线不足以证明 RISC 设计 |
| 几何与视觉变化下是否稳健 | 官方 None、Equi、Inv、Full | 只解释官方扰动范围内的结果 |
| 通用操作码能否用于不同原生机器人 | 官方任务与机器人绑定下共用 ISA | 支持多形态部署；不能据此宣称同任务跨机器人零样本迁移 |

CVPR 的研究定位建议突出视觉条件下的可执行操作表示、组合与可靠执行。仅提供一组函数名并展示 token 减少，方法贡献较弱；这是研究判断，不是录用标准。与既有 DexISA 的差异应说明双臂资源、接触关系、持续目标和组合执行带来的实际技术变化，不能只靠更名或新增机器人。

[Code as Policies](https://code-as-policies.github.io/) 已研究语言模型生成机器人程序；[VoxPoser](https://voxposer.github.io/) 已研究视觉条件下可组合的机器人操作表示。论文需要讨论差异。下面的共享控制器程序基线是本项目适配基线，不能未经复现就标成这些论文的原始方法成绩。

## 当前实现与实验前置条件

本地 README 与运行验证记录表明：六个操作码已有执行路径，当前主要验证空闲空间动作、局部接触、准静态抓持和单轴施力；对象级 MOVE、共享物体的双臂协调、Wuji 原生灵巧抓持和完整 Bench2Dex 任务尚未全部验收。RGB 已能回传，但没有完成视觉目标估计与视觉伺服，当前状态来源仍标为 simulation_privileged。

因此先用 UR5＋Wuji 官方任务 21 和 27 完成环境、Agent、动作与评分的端到端接通。这是开发阶段，不以两个装箱任务替代完整论文证据。现有单元测试和小型物理验收也不能填入任务 SR 表。

完整实验前需完成：原生任务配置清单、必要适配器、公共观测接口、实际模型遥测、独立评分、Direct 执行链，以及主实验所需的指令参数组合。任何尚未支持的任务在完整配置表中显式保留，不得因测试结果不佳移除。环境或资产无法加载的问题先修复；不能加载的任务若仍缺失，结果必须标为子集。

## 任务和机器人范围

[Bench2Dex 项目页](https://bench2dex.github.io/) 报告 26 个原生任务与机器人配置、12 种双臂灵巧手形态，官方展示每个配置每个通道 50 回合。任务与机器人并非完全交叉。完整方案保留这 26 个原生配置，不做 26×12 的笛卡尔积，也不把所有任务强行换成 UR5＋Wuji。

任务清单由固定版本官方发布清单产生。本地核对版本为 fd90dcc625b66c2e535a8b25bcf75bc81c7b080d，正式运行前再次冻结仓库、资产、任务 YAML、评价器、Isaac Lab 和 PhysX 版本；该版本中的场景文件不能仅按编号最大值推断任务数量。

None、Equi 和 Inv 遵循官方锚点关系；Full 的场景独立于其他通道采样，但同一个 Full 初始化应恢复给两种接口。每个方法对使用相同已保存初始化，而非仅使用相同 seed 名称。运行顺序按配对块随机化，避免模型服务时段或机器负载与接口组别重合。

当前 UR5＋Wuji 优先级不变。扩展到其他原生机器人是完整论文方案的后续工作，不表示现有适配器已经可用。仅在两个官方 Wuji 任务上的结果应命名为 UR5＋Wuji 子集。

## Agent 与模型选择

主实验固定一个公开、轻量的 Agent 循环：观察、推理、调用工具或编写程序、获取执行反馈、继续操作。四个模型共享任务提示、可访问文件、图像工具、代码执行环境与上下文整理规则；只做必要的厂商消息格式转换。模型原生推理参数分别记录，不能认为不同厂商的 high 代表相同计算量。

| 层级 | 建议配置 | 用途 |
| --- | --- | --- |
| 主实验 | 统一循环＋GPT-6.1 Sol，high | 闭源推理与编码配置 |
| 主实验 | 统一循环＋Claude Sonnet 5.5，high | 第二厂商配置 |
| 主实验 | 统一循环＋Gemini 3.8 Flash，冻结原生 thinking 设置 | 第三厂商配置 |
| 主实验 | 统一循环＋Qwen3.5-27B，冻结权重、精度与 thinking 设置 | 开放权重视觉模型 |
| Agent 外部验证 | 原生 Codex＋与主实验相同的 GPT 配置 | 检验原生上下文管理和工具编排下的效果 |
| Agent 外部验证 | Claude Code，经 Claude Agent SDK，搭配相同 Claude 配置 | 检验另一套原生 Agent 系统 |
| 可裁剪扩展 | Qwen-Agent＋相同 Qwen 权重；或 GPT-6 Astra 强模型配置 | 分别补充框架变化或模型能力变化，不混成同一种证据 |

候选依据为核对当日的 [OpenAI 模型目录](https://developers.openai.com/api/docs/models)、[Claude 模型目录](https://platform.claude.com/docs/en/models/overview)、[Gemini 模型目录](https://ai.google.dev/gemini-api/docs/models) 与 [Qwen 模型卡](https://huggingface.co/Qwen/Qwen3.5-27B)。这是选择建议，尚未验证账户访问、图像工具兼容性、费用遥测与具体端点稳定性。接入依据为 [Codex SDK](https://learn.chatgpt.com/docs/codex-sdk)、[Claude Agent SDK](https://github.com/anthropics/claude-agent-sdk-python) 和 [Qwen-Agent](https://github.com/QwenLM/Qwen-Agent)。

正式实验前固定模型 ID、可用 snapshot 或权重 revision、Agent 版本、工具 schema、上下文上限、推理与输出配置。没有不可变版本时记录实际响应模型标识和运行日期，并交错运行方法对。不得根据正式测试成绩更换模型、提示词或推理档位。

图表必须区分统一循环的模型配置与原生 Agent 软件。主实验不是四套不同的软件 Agent，原生系统验证也不能只用 GPT 的 ManipISA 去对比 Claude 的 Direct。

## 两个主对照组

| 组别 | 可用接口 | 允许行为 |
| --- | --- | --- |
| Direct | 原生机器人 SDK、文档、双方共有的基础计算与感知工具 | 可写 Python、调用 IK、发送关节或末端目标、执行轨迹与反馈控制、调试和恢复 |
| ManipISA | 相同公共资源，加六条操作码与其运行时 | 通过指令组合表达动作，使用统一查询、取消、维持与控制移交协议 |

两组只改变操作接口及其配套运行时支持，不改变语言目标、场景、观测权限、硬件或官方评价器。Direct 不要求每物理步请求模型，也不限制为逐关节输出。关节与笛卡尔调用不是新的主实验组。

主结果默认 ManipISA 的物理动作通过指令执行；通用代码工具可处理感知、计算与编排。若允许绕过 ISA 直接写关节，则作为明确命名的混合接口配置另报，不能仍称为纯 ManipISA。Direct 能使用原生 SDK 中已经存在的反馈控制能力；不得偷偷移除这些能力制造差距。

主对照体现系统整体收益。ManipISA 中额外实现的闭环控制器本身可能贡献效果，必须依靠后面的共享控制器实验分析，不能将全部收益归于指令条数。

每个回合使用隔离会话与工作区，双方相同的任务无关文档、非测试任务示例和安装依赖。不得提供测试任务的完整求解脚本、示范未来动作、成功位或阶段完成标签。所有方法允许的记忆规则相同；回合内生成的代码不能无成本带入后续回合。

## 观测协议和视觉证据

建议论文主轨道采用视觉条件执行：官方相机 RGB、允许的深度及标定、机器人本体状态；当前设计保留的结构化接触反馈对双方完全相同，不新增 TacMap 接口。所用传感器组合必须在论文中明确，这是 Bench2Dex 任务上的 Agent 观测协议，不能冒充官方训练策略的同观测复现。

物体实时位姿、接触区域和目标坐标系需要来自共同可用的视觉估计模块或 Agent 的图像推理。若提供公共感知模块，其版本、输入、误差与计算费用相同并冻结，输入不得包含当前物体仿真真值。Direct 得到同样的估计结果与几何计算能力。静态机器人标定和已公开资产尺寸可作为公共先验，必须区分先验与实时真值。

运行时同样受到观测权限限制。若 Agent 只看 RGB，而 ManipISA 在内部持续读取真实物体位姿进行控制，系统不能称为无特权视觉闭环。仿真接触力作为模拟传感反馈使用时应披露来源，并给 Direct 同等访问权；评价器独享的隐藏状态不能流入动作工具。

另做 Oracle-state 诊断：两组都获得相同的物体与接触真值，用于区分感知和执行瓶颈。该轨道与视觉主轨道分表，不能替代视觉结果。比较轨道时固定除状态来源以外的因素，并检查视觉被遮断后是否真的影响对象绑定；这属于泄漏审查，不另建测试任务。

当前仅有 RGB 回传还不足以支持这条主轨道。若视觉估计链在投稿前未完成，应把论文准确定位为特权状态下的操作接口研究；不能只加一张相机图就声称视觉操作能力。这是当前最重要的研究风险之一。

## 主实验矩阵与规模

完整设计以 T=26 个官方配置、C=4 个官方通道、N=50 个场景初始化、M=4 个模型、I=2 个接口为基础。N=50 是对齐官方展示规模，不是显著性的保证。一个重复编号代表独立 Agent 会话或采样；同一环境初始化的多次模型采样保留聚类关系。

| 实验 | 配置 | 新增回合数 |
| --- | --- | ---: |
| 完整主实验第一轮 | 26×4×50×4 模型×2 接口×1 次采样 | 41,600 |
| 完整主实验三次采样 | 上述每个初始化独立执行三次；含第一轮 | 124,800 |
| 原生 Agent 验证 | 26×2 通道×25 初始化×3 次×2 Agent×2 接口 | 15,600 |
| 机制实验 | 26×2 通道×25 初始化×3 次×2 主模型×3 额外变体 | 23,400 |
| Oracle-state 诊断 | 26×2 通道×25 初始化×3 次×2 主模型×2 接口 | 15,600 |
| 较低费用预算曲线 | 26×2 通道×25 初始化×3 次×2 主模型×2 接口×2 额外预算 | 31,200 |

原生 Agent、机制、Oracle 和预算曲线采用 None 与 Full，初始化预先固定为主实验每单元前 25 个样本。机制变体的完整 ManipISA 对照复用主实验相同样本与配置，不重复付费；有版本变化则不能复用。两个主模型预先指定 GPT 与 Claude，不按测试成绩选择。

全部模块合计 210,600 回合，其中三次采样完整主实验为 124,800 回合。这是完整研究规模，不是建议立即全部启动。正式模型采样无法固定随机种子时仍使用独立会话，并如实记录模型服务的不确定性。结果报告平均表现，不能取三次中的最好成绩或使用 best-of-3 冒充一次执行 SR。

## 评分标准

评分以 [ManipISA 总评分标准](manipisa-overall-scoring.md) 为唯一规范。用户确定每个模型的 Direct／ManipISA 各自计算 Overall，任务完成程度、执行可靠性、成本效率占比分别为 30%、30%、40%；成本内部墙钟时间、Native tokens、模型请求数为 5∶4∶1。通用性不加分，美元费用单独报告。

Bench2Dex 提供回合稳定成功 S、阶段进度 P 和无硬违规标志 H。本稿默认 A=S+(1−S)×0.25×P 表示完成程度，R=S×H 对应安全成功，E=0.5e_T+0.4e_U+0.1e_K 为原始成本效率。保留任务质量约束的有效成本分 C=A×H×E。总分为 Overall_i=30A+30R+40C。部分进度折扣 0.25、成本门控及线性归一化为本项目设计选择，不属于官方评价方式或用户指定的一级权重。

先计算每个回合的分数，再对任务与通道等权汇总。原始 SR、SafeSR、LSCR、硬违规、仿真成功耗时和全回合成本同时报告。不得把 Agent 或指令自报成功当成官方成功，不得平均后再把质量与效率相乘。缺失必需计量时 Overall 为 N/A，缺失美元不影响本版评分。

可靠成功的回合为 60～100 分；成功但有官方硬违规为 30 分；普通失败最多 17.5 分，零进展不靠成本获得分数。此规则替代先前合并任务质量的 60／40 公式；硬违规不再使任务完成项一起清零。

墙钟由统一单调时钟计量，token 只用权威原生 usage，请求数在实际发起时计数。DexISA 计量复用、失败重试、累计事件去重、计时边界、归一化尺度与算例均详见总评分规范。参考值尚需开发数据校准并冻结，当前未运行评分器。

## 费用与时间预算

每个主实验配置采用同一官方物理预算和同一模型费用上限 B0。B0 必须在开发回合确定并冻结，不能依据正式结果调整。预算曲线采用 B0/4、B0/2、B0；每个预算重新执行，因为 Agent 得知预算后可能改变策略，不能仅从高预算日志事后截断推算。

B0=3 美元可作为与 BVB 类似的开发候选，不是已确定的 ManipISA 预算，也不是本方案授权的支出。开发阶段需测量各模型两种接口的费用分布和达到上限的比例，选择能够回答研究问题且可承担的 B0。墙钟设置共同的终止上限并报告超时率；物理、美元和墙钟预算不能互相替代。正式上限在实验注册表中填实后才能启动。

每回合费用为各次模型调用费用之和。费用平均的分母包括失败回合，不是成功回合。输入、输出、缓存读取与写入等按各提供方真实分类换算；推理 token 已包含在输出时不再次收费。保留原生 usage、价格日期、提供方和请求标识，区分按价目表估算与账单核对值。

主 Agent spend 排除官方评价器及公共仿真运行费用；Agent 专用的辅助模型或感知 API 调用必须计入。共享感知和本地计算另报统一成本边界，不能给某一组免费使用隐藏的额外模型。订阅版 Agent 不用月费除以回合数冒充 API 成本；无法核验时保留 token 与时间、将美元标 N/A。

Qwen 可使用固定权重的托管或本地部署。只要 T、U、K 与任务评价完整，美元费用缺失不阻止计算新版 Overall；部署条件须明确标注。本地 GPU 成本不能冒充 API 费用或写成零美元。若使用不同的运行预算协议，配置应分组报告；可计算同一评分公式不等于实验条件完全相同。

模型等待期间建议仿真同步暂停，已提交动作片段或控制循环按相同物理时钟推进，两组均允许批量动作与本地反馈循环。该设置测量仿真任务完成能力，不代表实时部署；若后续测实时模式，必须独立报告。

## 三项机制实验

这些实验使用同一批 Bench2Dex 任务，保持两个主对照组不变，在单独的机制表中增加变体。每个变体只改变预定因素，共用执行器增益、感知模块、控制频率、动作限值和基础紧急停止条件。

| 变体 | 唯一主要变化 | 检验的问题 |
| --- | --- | --- |
| Code＋同一控制器库 | 将 ManipISA 所使用的实际底层控制器与相关状态查询以普通函数库提供给 Agent，自行写程序编排；不提供完整 ISA 契约协议 | 收益是否超过额外提供成熟控制器的效果 |
| 展开的等价接口 | 将六条指令中合并的模式与目标类别展开成独立工具；仍映射到同一后端和完全相同的物理能力 | 精简接口的组合表达是否比更多独立工具更有效 |
| 无持续契约监测 | 保留相同控制律和基础限幅，仅移除运行时额外的阶段不变量监测及结构化违约反馈 | 执行契约是否贡献可靠性与恢复效果 |

展开接口的具体条数在等价映射审查后固定，不先任意指定 10 或 20 条。两种接口共享同一组规范化执行路径和信息完整的文档；不得故意重复长文档或使用难懂名字弱化展开版。需要检查语义等价与少量开发程序的执行一致性，但这些检查不是新增 benchmark 任务或论文主评分。

去监测变体不得顺便取消闭环控制或所有安全限幅；否则变化因素过多。未能在实现上分离的因素应改名并缩窄解释。上述对照只能提供关于表示与运行机制的经验支持，不能证明六条是数学最小或唯一最优指令集。

## 统计与结果解释

主要报告每个模型的配对 ΔOverall 及 95% 置信区间，同时保留绝对 Overall、SR、ΔSR 和所有组成项。使用配对初始化为重采样单元；同一锚点的多次 Agent 采样及关联通道保留为一个聚类，Full 按其独立初始化分层。建议采用 10,000 次 bootstrap。以固定 26 个任务集为条件估计区间，不把它解释成任意机器人任务总体的置信区间。

四个模型的主要效果分别报告；若给显著性结论，对四个主比较采用 Holm 校正。次要指标与消融按预先声明的问题解释，不从大量切片中挑显著结果。预算曲线与前沿同时显示不确定性，不能凭很小的点估计差异断言支配。

Overall 的最小关注差异尚需在开发阶段确定；SR 可继续以 5 个百分点作为样本规划示例，但不能直接当作 Overall 的阈值。开发数据用于估计配对分数差的方差及 SR 配对不一致率，检验样本规模是否能区分目标效应；正式结果不能用于反复加样本直到显著。若预算不足造成宽区间，直接报告证据不确定。

降低成本必须结合 SR 解读，提前失败也会减少 token 和耗时。可以补充在相同成功率附近的成本关系，但不能在未观测的预算区间外推。无显著差异不等于两方法等价；若要声称成功率不下降而成本减少，需事先另设非劣效界值及相应检验。

## 跨任务与跨机器人声明

在开发清单上调整通用执行器后冻结代码与任务无关提示，正式测试禁止按失败任务加入专门分支。至少保留一份完全未参与接口与控制器调参的官方任务配置清单，单独报告成绩；开发过的官方任务可出现在全表，但不能称为未见任务。

开发和保留清单需在首次任务性能试跑前形成。当前尚无完整任务参数支持审查，因此本稿不虚构具体的训练测试划分。正式清单必须按任务类型与原生机器人分组制定，并公开开发接触范围；预算裁剪也必须沿用这份清单，不能按成绩挑任务。

跨机器人结果展示相同六条操作码和公共契约在不同适配器上的执行。由于 Bench2Dex 不提供每个任务对每个机器人的完全交叉配置，多形态成绩混有任务差异。不同机器人上的性能差值不能证明跨机器人迁移，本文不为证明迁移而新建换机器人任务。

## 预算裁剪与执行顺序

完整方案的执行顺序为：先完成两项 Wuji 任务的端到端开发，再冻结观测、接口与版本，随后覆盖所有计划官方配置，最后进行原生 Agent 验证和机制分析。性能测试前保存实验注册表与预算，不因某模型结果更好而优先为它扩大样本。

| 档位 | 建议保留 | 规模与限制 |
| --- | --- | --- |
| 完整研究 | 四模型、全 26 配置、四通道、50 初始化、三次采样，加全部分析 | 210,600 回合；需先估算 API 和仿真吞吐成本 |
| 完整覆盖基础版 | 四模型、全 26 配置、四通道、50 初始化、一次采样 | 主实验 41,600 回合；没有独立重复的任务单元不可声称已充分估计 Agent 随机性 |
| 预算优先论文版 | 三模型、全 26 配置、四通道、25 初始化、两次采样，保留关键共享控制器与展开接口对照 | 主实验 31,200 回合；与官方 50 初始化协议有差别，标明不同初始化数；三模型建议 GPT、Claude、Qwen，优先裁掉第四厂商 |
| 开发验证 | UR5＋Wuji 两项官方任务、少量独立开发初态 | 只验证链路，不能替代全套论文主实验 |

优先裁掉第五个模型、额外推理档位、第三套原生 Agent 和重复的辅助图；随后调整采样次数。保留任务广度、Direct 能力公平、视觉证据与核心消融。不能只留下最容易成功的任务。完整规模不是 CVPR 要求，更大的回合数也不保证录用。

总 API 预算应按每个配置回合数乘开发测得平均费用求和，再加开发、基础设施补跑与辅助模型费用；同时估算仿真 GPU 小时与 API 速率限制。以主实验三次采样的 124,800 回合为例，假设每回合 0.10 美元则约 12,480 美元，假设 1 美元则约 124,800 美元；这是敏感性算例，不是费用预测。模型费用上限也不等于实际均值。

## 投稿前需要达到的证据边界

[CVPR 2027 官方征稿](https://cvpr.thecvf.com/Conferences/2027/CallForPapers) 包含 embodied vision、agentic AI 与 physical AI，公布的论文提交截止为 2026 年 11 月 16 日 AOE。本稿只据此确定投稿时间背景，实验数量与配置由研究问题决定。

投稿前至少要能准确回答：六条通用指令相对既有 DexISA 和普通控制库新增了什么；视觉信息如何进入可执行目标；官方任务与原生形态实际覆盖多少；不同模型的收益是否可复现；共享控制器后收益是否还存在；成本下降是否伴随任务质量下降。

若上述关键链路未完成，应收窄论文声明或延后结论，而不是用玩具验收、隐藏真值、弱化 Direct 或自定义成功率填补。当前最优先的工作是官方任务端到端可运行、真实灵巧接触执行与共同视觉观测，不是再增加模型数量。
